## 2.1 PTA接口实现

> **章节说明**：说明实现逻辑，非完整代码实现。如PTA接口有新增修改，需在此处说明。

**函数原型**

```
npu_ai_infra_matmul(Tensor self, Tensor mat2, int cube_math_type=0) -> Tensor
```

**参数说明**

- **self**（`Tensor`）：必选参数，进行matmul计算的输入左矩阵。要求是一个2D的Tensor。
- **mat2**（`int`）：必选参数，进行matmul计算的输入右矩阵，ND格式下仅支持2维，NZ格式下仅支持4维。
- **cube_math_type**（`int`）：可选参数，表示matmul计算的数据类型，当前仅支持0。

**返回值说明**

- **Out**（`Tensor`）：计算结果， 数据类型支持`float16`、`bfloat16`、`float32`，数据类型与`input`需要保持一致，数据格式要求为ND。不支持非连续Tensor。

## 3.3 迁仓策略与差异点

### 3.3.1 迁仓策略

本需求将NN仓matmulV3算子整体迁移至omni-ops仓，代码结构保持与Matmulv3算子一致，包含op_api、op_host、op_kernel、tests等完整目录。迁仓后算子名称改为 `AiInfraMatmul`，aclnn接口名改为 `aclnnAiInfraMatmul` / `aclnnAiInfraMatmulWeightNz`。

### 3.3.2 与源算子（NN仓matmulV3）的差异点

| 差异项 | NN仓matmulV3 | omni-ops AiInfraMatmul | 原因 |
| ------ | ------------ | ---------------------- | ---- |
| matmul路由逻辑 | 部分shape走v2通路 | 所有shape统一走v3通路 | v2不支持superKernel，v3规避全核同步 |
| 多核切K模板 | 使能SINGLE_CORE_SPLIT_K(2)/DETERMINISTIC_SPLIT_K(3)/MULTI_CORE_SPLIT_K(4)/SINGLE_CORE_NKM_SPLIT_K(5)/SINGLE_CORE_SPLIT_K_GM_TO_L1(6) | 所有切K模板均不使能，仅保留BASE_SPLIT_K(0) | 切K模板涉及全核同步(SyncAll)，与superKernel融合冲突 |
| 图模式 | 支持GE入图+AclGraph | 仅支持AclGraph，不支持GE入图 | omni-ops仓推理场景仅需AclGraph |
| aclnn接口范围 | 支持Matmul/Addmm/InplaceAddmm/WeightNz等多种接口 | 仅支持aclnnAiInfraMatmul和aclnnAiInfraMatmulWeightNz | omni-ops仓自定义算子场景仅需这两个接口 |
| 平台支持 | 多平台 | ascend910b, ascend910_93 | 按需裁剪 |

### 3.3.3 路由逻辑修改说明

**matmul路由修改**：原始NN仓aclnn适配层中，`MatmulCommonProcess` 根据shape条件判断走v2还是v3通路。迁仓后修改为所有shape均走v3通路，通过 `matmul_v2tov3.cpp` 中的 `MmCheckHitV3Shape` 和 `BmmCheckHitV3Shape` 始终返回true实现。

**多核切K禁用说明**：在 `ai_infra_matmul_base_tiling.cpp` 的 `DoSelectTiling` 函数中，将包含全核同步的多核切K分支注释掉。`MULTI_CORE_SPLIT_K` 相关逻辑在 `DoOpTiling` 中通过 `SupportMultiSplitK` 返回false跳过。kernel侧 `ai_infra_matmul_tiling_key.h` 中保留所有模板参数定义保持兼容，但tiling不会选择这些模板对应的TilingKey。

## 3.4 TilingKey设计

> **章节说明**：说明TilingKey的设计原则，使用表格形式给出各个TilingKey的含义或者各个字段的含义。

TilingKey通过6个模板参数组合编码：

| 字段 | 位宽 | 取值范围 | 含义 |
| ---- | ---- | -------- | ---- |
| LOADMODE | 4bit | 0=BASE_FULLLOAD, 1=AL1_FULLLOAD, 2=BL1_FULLLOAD | L1加载策略 |
| SPLITCOREMODE | 8bit | 0=BASE_SPLIT_K, 2=SINGLE_CORE_SPLIT_K, 3=DETERMINISTIC_SPLIT_K, 4=MULTI_CORE_SPLIT_K, 5=SINGLE_CORE_NKM_SPLIT_K, 6=SINGLE_CORE_SPLIT_K_GM_TO_L1 | 核间切分策略 |

| SPECIALOPT | 4bit | 0=K_NOT_SHIFT, 1=K_SHIFT | 特殊优化（K轴错峰） |
| FP32ADDMM | 4bit | 0=DISABLE, 1=ENABLE | FP32 addmm内存优化 |

> **迁仓说明**：SPLITCOREMODE字段原始支持0/2/3/4/5/6共6种取值，迁仓后仅使能BASE_SPLIT_K(0)，其余切K模式（2/3/4/5/6）均禁用，以规避全核同步问题、支持superKernel融合。

# 4 模板设计

> 模板设计与NN仓matmulV3一致，本章节保留原始结构，仅标注迁仓差异点。原模板的完整计算流程、Buffer设计、Kernel伪代码等参见NN仓matmulV3详细设计文档。

## 4.1 Base FullLoad计算模板（ND格式，BASE_SPLIT_K）

### 4.1.1 计算流程图

与Matmulv3算子一致：Host侧依次执行GetPlatformInfo -> GetShapeAttrsInfo -> DoOpTiling -> DoLibApiTiling -> DoSelectTiling -> DoNd2NzVectorTiling -> SetRunInfo -> 计算TilingKey；Device侧根据模板参数选择MatmulBaseKernel/MatmulBaseKernelAL1FullLoad/MatmulBaseKernelBL1FullLoad/MatmulCvpBaseKernel，根据transA/transB组合实例化4种转置模式。

> **迁仓差异**：`DoSelectTiling` 中 SINGLE_CORE_SPLIT_K 和 DETERMINISTIC_SPLIT_K 分支已注释，不会走到全核同步模板。

### 4.1.2 Tiling实现设计

#### 4.1.2.1 TilingData设计

与Matmulv3算子一致， `MatmulTilingData` 结构体。具体字段定义参见 `op_kernel/ai_infra_matmul_tiling_data.h`。

```cpp
struct MatmulTilingData {
    TCubeTiling matmulTiling;          // 高阶API tiling数据
    L2cacheTilePara tileL2cacheTiling; // L2 cache tiling参数
    MatMulRunInfo matmulRunInfo;       // 运行时信息(转置/nd2nz/数据格式)
    L2cacheUseInfo l2cacheUseInfo;     // L2 cache使能标志
    uint32_t baseAN;                   // A矩阵ND2NZ baseN
    uint32_t baseAD;                   // A矩阵ND2NZ baseD
    uint32_t baseBN;                   // B矩阵ND2NZ baseN
    uint32_t baseBD;                   // B矩阵ND2NZ baseD
};
```

#### 4.1.2.2 核间tiling策略和数据地址偏移计算

与Matmulv3算子一致，采用BASE_SPLIT_K模式：按M轴和N轴将输出矩阵切分到多个核，根据blockIdx计算各核负责的输出区域偏移。

> **迁仓差异**：原始NN仓支持6种核间切分模式，迁仓后仅保留BASE_SPLIT_K。

#### 4.1.2.3 核内tiling策略和数据地址偏移计算

与Matmulv3算子一致，通过 `MultiCoreMatmulTiling` 高阶API计算 baseM/baseN/baseK、stepM/stepN/stepKa/stepKb、depthA1/depthB1 等核内tiling参数。

### 4.1.3 Buffer设计

与Matmulv3算子一致。Base模板不做UB空间分配，由高阶API Matmul内部管理。L1/L0A/L0B/L0C由高阶API根据tiling参数动态分配。workspace在BASE_SPLIT_K模式下仅保留20MB。

> **迁仓差异**：NN仓中SINGLE_CORE_SPLIT_K和DETERMINISTIC_SPLIT_K需要额外workspace存储切K中间结果，迁仓后不涉及。

### 4.1.4 Kernel设计

与Matmulv3算子一致。kernel入口根据编译期模板参数分发至不同kernel类（MatmulBaseKernel、MatmulBaseKernelAL1FullLoad、MatmulBaseKernelBL1FullLoad、MatmulCvpBaseKernel），内部根据transA/transB组合实例化4种转置模式的MatmulType。

### 4.1.5 异常场景设计

与Matmulv3算子一致，包括：空Tensor返回全零输出、空指针/dtype/shape/cubeMathType校验报错、WeightNz场景的k=1/n=1/维度/format限制等。

### 4.1.6 支持确定性计算设计

与Matmulv3算子一致。BASE_SPLIT_K模式下默认确定性实现。由于多核切K模板已禁用，不存在核间累加顺序导致的非确定性问题。

### 4.1.7 精度分析及设计

精度与Matmulv3算子一致。cubeMathType精度控制仅支持为0（KEEP_DTYPE）。

### 4.1.8 性能分析及设计

与Matmulv3算子一致。保留Double Buffer、L2 Cache优化、K轴错峰、L1全载、Preload等优化手段。

### 4.1.9 训推一致性设计

本算子不涉及训推一致性问题。

## 4.2 NZ格式计算模板（mat2为NZ格式）

与Matmulv3算子一致，区别在于mat2的Format为FORMAT_FRACTAL_NZ，kernel编译时format_x2=CubeFormat::NZ，仅使能Base FullLoad + KShift 和 Base FullLoad + NoPreload两个模板，均为AIC_ONLY。TilingData、Buffer设计、Kernel设计等与4.1节一致。
