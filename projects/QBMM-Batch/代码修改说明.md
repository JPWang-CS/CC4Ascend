# QBMM MX 全量化 batch 维支持 — 代码修改说明

> 分支 QBMM0 vs upstream/master，6 文件，+122 / -32 行

## 修改目的

MX 全量化（quantMode=mxfp8/mxfp4）的 pertoken/x2Scale 原本固定 3D `[M,K/64,2]` / `[K/64,N,2]`，无法支持 batch > 1 场景。本次修改让 scale 维度动态适配：**有 batch 时 4D/5D，无 batch 时仍 3D，完全向后兼容**。

---

## 关键常量说明

### 为什么 scale 最后一维固定为 2

> 常量：`MXFP_MULTI_BASE_SIZE = 2`

MX 的 scale 类型是 **e8m0**（8-bit 纯指数），单个 1 字节。但 Ascend NPU 的 Vector 单元最小存取粒度为 **16-bit（half）**，单个 e8m0 不够对齐。硬件将 **2 个 e8m0 打包成一个 uint16** 存放，指令加载时自动解包为两个独立 scale 值。这跟精度无关，是 **Ascend 硬件存取粒度**决定的数据排布约束。

### 为什么 K 维要除以 64

> 常量：`MXFP_DIVISOR_SIZE = 64`（全层统一：op_api/op_host/op_kernel 各定义一份）

MX 是 **per-group 量化**：每 64 个元素沿 K 方向共享一个 e8m0 scale 值。所以 K=192 对应 `K/64 = 3` 个 scale block。scale 的第一维 = `ceil(K/64)` = block 数。64 这个值来自 MX 规范定义的 block size（也叫 subchannel/group size），是 MXFP8/MXFP4 标准的一部分——不是随意选的，K 维必须以 64 对齐 pad。

### scale shape 含义（transB=0 为例）

```
x2Scale  shape = [K/64,  N,  2]
                   ↑     ↑   ↑
             block数   列数  2个e8m0打包成uint16
```

## 修改逐文件说明

### 1. `op_api/quant_matmul_checker.cpp`（核心，+42/-19）

**改了什么：** MX scale 的维度索引从硬编码改为 batch-aware 动态计算。

**修改点：**
- `CheckDimValueMicroScaling()` — K/M/N dim 索引：`transX?1:0` → `batchDimNum + (transX?1:0)`
- last dim 检查：`GetDim(MX_SCALE_DIM - 1)` → `GetDim(GetDimNum() - 1)`
- `InferGroupSizeM/K/N()` — 同上 batch-aware 索引
- `CheckMxScaleDimRange()` — 校验从 `== 3` 改为 `>= 3`；新增 batch 维数量对齐检查 + per-batch 值相等检查

**为什么：** 无 batch 时 `GetDimNum()==3`，`batchDimNum=0`，行为与旧代码完全一致。有 batch 时 batch 维 prefix 到 scale 前面，索引自动偏移 batch 维数。

### 2. `op_api/aclnn_quant_matmul_v4.cpp`（+5/-1）

**改了什么：** `CheckDimRange()` 中 scale 维数校验从精确匹配改为范围校验。

**为什么：** 硬编码 `MX_SCALE_DIM_NUM`(3) 会拦截 batch 场景的 4D/5D scale。改为 `>=3 且 <=MAX_DIM` 后 3D~5D 均放行。

### 3. `op_host/op_tiling/arch35/quant_batch_matmul_v3_checker.cpp`（+54/-11）

**改了什么：** tiling 层 checker 同步改造。
- `MxPertokenScaleShapeCheck()` — mDimIdx/kDimIdx batch-aware
- `MxScaleShapeCheck()` — kDimIdx/nDimIdx batch-aware；维数校验 `!=3` → `<3`
- **新增 `CheckBatchValidInMxPerGroupMode()`** — 校验 scale batch 维数与 x1/x2 batch 维数对齐，per-batch 值相等
- `CheckInputValidInMxPerGroupMode()` — 新增 x1Shape/x2Shape 参数传递给 batch 校验

**为什么：** 与 op_api 层一致，tiling 层也需要 batch-aware 的维度索引。op_host 层的报错信息独立于 op_api 层，必须同步修改。

### 4. `op_host/op_tiling/arch35/quant_batch_matmul_v3_checker.h`（+3/-0）

**改了什么：** 新增两个函数声明，函数签名增加参数。

### 5. `matmul/common/cmct/kernel/kernel_qbmm_mx.h`（+8）

**改了什么：** X1SCALE/X2SCALE 的地址计算增加 `AddBatchOffset`。

**为什么：** batch 场景下 scale tensor 有 batch 前缀维，kernel 需要按 batch 索引偏移到正确位置取对应的 scale 数据。

### 6. `cmake/third_party/ops-tensor.cmake`（+1/-1）

依赖版本号更新。

## 向后兼容性

| 场景 | `GetDimNum()` | `batchDimNum` | 行为 |
|------|:---:|:---:|------|
| 旧：无 batch（3D scale） | 3 | 0 | 索引计算等价 `transX?1:0`，与旧代码一致 |
| 新：batch=2（4D scale） | 4 | 1 | scale[0] 对齐 x[0]，K/M/N 索引从 scale[1] 开始 |

旧 UT 用例全部覆盖 3D 路径，修改不改变其语义。
