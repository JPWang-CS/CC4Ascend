## 1. ⚠️ 中等问题

### 1.1 `CHECK_RET` 无错误日志（op_api 层）

**位置**：`quant_matmul_checker.cpp:1011-1022`（`CheckMxScaleDimRange`）

```cpp
CHECK_RET(x1BatchDimNum == x1InputBatchDimNum, false);  // 失败时无日志
CHECK_RET(x2BatchDimNum == x2InputBatchDimNum, false);
for (size_t i = 0; i < x1BatchDimNum; ++i) {
    CHECK_RET(x1ScaleShape.GetDim(i) == x1Shape.GetDim(i), false);  // 用户不知道哪个 dim 错了
}
```

`CHECK_RET` 宏定义为 `if (!cond) return_expr`，失败时**不输出任何诊断信息**。batch 维数不对或某个 batch dim 值不匹配时，用户只能看到最外层 `ACLNN_ERR_PARAM_INVALID`，无法定位到具体是哪个维度、期望多少、实际多少。

**建议**：参照同文件其他校验的风格，改用 `OP_LOGE_FOR_INVALID_VALUES_WITH_REASON` + `return false`，打印出具体的期望值和实际值。例如：

```cpp
if (x1BatchDimNum != x1InputBatchDimNum) {
    OP_LOGE_FOR_INVALID_SHAPEDIM_WITH_REASON(apiName_, GetX1ScaleName().c_str(),
        FormatString("%zu batch dims", x1BatchDimNum).c_str(),
        FormatString("x1 has %zu batch dims, scale must match", x1InputBatchDimNum).c_str());
    return false;
}
```

> 注：该文件中 `InferGroupSizeM/K/N`（行 698-700）也用了无日志的 `CHECK_RET`，属于已有风格，但新增的 batch 校验报错概率更高（用户更容易传错 batch 维数），建议补充日志。

### 1.2 常量重复定义（op_api ↔ op_host 不一致风险）

**位置**：
- `op_api/quant_matmul_checker.cpp:40` — `static const size_t MX_SCALE_MIN_DIM_WITH_BATCH = 3;`
- `op_host/.../quant_batch_matmul_v3_checker.cpp:30` — `constexpr size_t MX_SCALE_MIN_DIM_WITH_BATCH = 3;`

相同的语义常量在 op_api 和 op_host 各定义一份，且修饰符也不同（`static const` vs `constexpr`）。如果 MX 规范的最小维度将来变化，需要改两处。

**建议**：提到 `matmul/quant_batch_matmul_v3/common/` 或已有的共享头文件中统一定义。（非阻塞，可后续 clean code 时处理）

## 2. 💡 建议改进

### 2.1 Kernel `AddBatchOffset` stride 计算注释可完善

**位置**：`kernel_qbmm_mx.h:305-313`

```cpp
// x1Scale/x2Scale batch offset. e8m0 is 1 byte and never packed, so no sizeShift here.
// Per-batch element count = M(or N) * ceil(K/64) * 2, matching the MX scale stride in GetQuantOffset.
Get<QuantBatchMatmul::IDX_X1SCALE_OFFSET>(blockOffset_) +=
    batchAOffset_ * params.problemShape.m *
    Cmct::Gemm::CeilDiv(params.problemShape.k, static_cast<int64_t>(MXFP_DIVISOR_SIZE)) * MXFP_MULTI_BASE_SIZE;
```

注释说 e8m0 1 byte 未 pack，但紧接着乘以 `MXFP_MULTI_BASE_SIZE(2)`。这里的 "pack" 指的是硬件存取对齐（2 个 e8m0 拼成 uint16），和注释的 "never packed" 容易让读者困惑。

**建议**：改为更明确的注释，例如：
```cpp
// e8m0 1B/elem. 2 e8m0 values packed into 1 uint16 for hardware alignment (MXFP_MULTI_BASE_SIZE=2).
// Per-batch stride = M * ceil(K/64) * 2 bytes. For transA, stride is commutative: ceil(K/64)*M*2 == M*ceil(K/64)*2.
```

### 2.2 tiling checker `CheckBatchValidInMxPerGroupMode` 冗余局部变量

**位置**：`quant_batch_matmul_v3_checker.cpp:666-669`

```cpp
auto x1ShapeLen = x1Shape.GetDimNum();
auto x2ShapeLen = x2Shape.GetDimNum();
```

`x1ShapeLen` 和 `x2ShapeLen` 各使用一次（在下一行的 `? :` 中），可以 inline 掉。极小问题，不改也无妨。

### 2.3 缺少 batch>1 的 UT 覆盖

当前所有 UT 用例（CSV 数据）均为 3D 无 batch 场景。本次改动虽然向后兼容（batchDimNum=0 时路径一致），但新增的 `CheckBatchValidInMxPerGroupMode` 和 `CheckMxScaleDimRange` 中 batch 对齐校验代码在 UT 中不会被执行到。

**建议**：至少新增一条 batch=2 的 CSV 用例，覆盖 batch 维对齐逻辑。

## 3. ✅ 确认正确的设计

以下点经过验证，逻辑正确：

| 检查项 | 结论 |
|--------|------|
| `OP_TILING_CHECK(scaleBatchLen != x2BatchLen, ...)` — 宏在 cond=true 时触发，`!=` 表示不等时报错 | 正确 |
| `CHECK_RET(x1BatchDimNum == x1InputBatchDimNum, false)` — 宏在 cond=false 时触发，`==` 表示不等时报错 | 正确 |
| Kernel stride `M * ceil(K/64) * 2` 对 transA=true/false 通用（乘法交换律） | 正确 |
| `batchAOffset_` 对应 x1Scale（pertoken 跟 x1 batch）、`batchBOffset_` 对应 x2Scale（跟 x2 batch） | 正确 |
| `GetDimNum() - 1` 代替 `MX_SCALE_DIM - 1`，无 batch 时 `GetDimNum()==3` 等价 | 正确 |
| scale dim 校验从 `== 3` 改为 `>= 3`，同时 op_api 的 `CheckDimRange` 已有 `MAX_DIM` 上限 | 正确 |
