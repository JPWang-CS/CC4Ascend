# 1 算子需求

## 1.1 设计约束

- 运行环境：A5（Ascend 950），Blaze TensorAPI 路径
- 调用方式：单算子 `aclnnQuantMatmulWeightNz`
- 适用算子：`quantBatchMatmulV3`，MX 全量化路径
- 设计原则：简洁、最小改动、向后兼容
- 涉及仓：
  - `ops-nn`（算子实现，校验层修改）
  - `ops-tensor`（Blaze TensorAPI 库，kernel 层修改）

## 1.2 需求描述

### 1.2.1 功能描述

MX 全量化场景，scaleX1/scaleX2 增加 batch 维度支持：

| | 变更前 | 变更后 |
|---|--------|--------|
| scaleX1 shape | `(m, ceil(K/64), 2)` | `(batchA, m, ceil(K/64), 2)` |
| scaleX2 shape | `(k, ceil(N/64), 2)` | `(batchB, k, ceil(N/64), 2)` |

batch 维度数与 x1/x2 的 batch 维度数一致，各维值逐维匹配。

### 1.2.2 适用范围

| 量化类型 | x1 dtype | x2 dtype | scale dtype | x1/x2 维度 | 涉及？ |
|---------|----------|----------|-------------|-----------|--------|
| mx 全量化 | F8_E4M3FN / F8_E5M2 | F8_E4M3FN / F8_E5M2 | F8_E8M0 | 2-6D | ✅ |
| mx 全量化 | F4_E2M1 | F4_E2M1 | F8_E8M0 | 2-6D | ✅ |
| mx A8W4 | F8_E4M3FN | F4_E2M1 (NZ) | F8_E8M0 | x1=2D | ❌ 无batch |
| mx A8W4 | F8_E4M3FN | FLOAT32 (ND) | F8_E8M0 | x1=2D | ❌ 无batch |

x1/x2 为 2D（无 batch）时不涉及；x1/x2 ≥ 3D（有 batch）时 scale 需对应 batch 前缀。

### 1.2.3 精度要求

精度继承原算子 MX 量化标准，满足 mxfp8/mxfp4 精度验收标准。

# 2 算子设计

## 2.1 总体设计

### 2.1.1 核心思想

Scale 维度模型从固定 3 维改为 `batchPrefix + MX3D`：

```
Scale Shape:  [batch_0, ..., batch_N] + [M/ceil(k/64), ceil(k/64)/N, 2]
               ← batchDimNum →           ← MX 固定 3 维 →
               batchDimNum = totalDimNum - 3
```

所有访问 M/K/N/Last 维度的索引统一为 `batchDimNum + offset`。batch 不存在时 `batchDimNum = 0`，退化为原逻辑。

### 2.1.2 与 GMM 的 batch 差异

| | GMM (grouped_matmul_finalize_routing) | QBMM V3 |
|---|------|------|
| batch 本质 | experts 分组，每组 M/N/K 不同 | MatMul 批量，所有 batch 共享 M/N/K |
| x 维度 | 始终 2D `(M, K)` | 2-6D `(batch, M, K)` |
| scale batch 来源 | groupList（experts 个数） | x1/x2 的 batch 维 |
| tiling | 按组独立计算 | 统一，batch 仅作计算量乘数 |
| 需新增 tiling 字段？ | 不需要（复用 groupList） | **不需要**（复用 batchA1-4 / batchB1-4） |

QBMM V3 的 scale batch 信息在 `QuantBatchMatmulV3BasicAPIDataParams` 中已存在（`batchA1-4` / `batchB1-4`），kernel 层直接用现有 batch 维计算 scale stride，不需要新增 tiling 字段。

### 2.1.3 调用链与改动分布

```
aclnn 入口 (aclnn_quant_matmul_v4.cpp)
  └─ CheckDimRange()            ← 第1关：!=3 → <3
       │
Checker (quant_matmul_checker.cpp)
  ├─ CheckMxScaleDimRange()     ← 第2关：!=3 → <3 + batch 逐维匹配
  ├─ CheckDimValueMicroScaling() ← 第3关：硬编码索引 → batchDimNum+offset
  ├─ InferGroupSizeM()          ← 同上
  ├─ InferGroupSizeK()          ← 同上
  └─ InferGroupSizeN()          ← 同上
       │
Tiling Checker (quant_batch_matmul_v3_checker.cpp)
  ├─ MxPertokenScaleShapeCheck() ← 第4关：!=3 → <3 + batch-aware 索引
  ├─ MxScaleShapeCheck()        ← 同上
  └─ CheckBatchValidInMxPerGroupMode() ← 第5关：新增 batch 逐维校验
       │
Kernel (ops-tensor: kernel_qbmm_mx.h)
  └─ AddBatchOffset()           ← 第6关：pertokenScale/scale GM 指针 batch 偏移
```

### 2.1.4 修改文件

| # | 文件 | 仓 | 改动 |
|---|------|-----|------|
| 1 | `op_api/aclnn_quant_matmul_v4.cpp` | ops-nn | `CheckDimRange`: gate 放行 |
| 2 | `op_api/quant_matmul_checker.cpp` | ops-nn | 5 个函数：`!=`→`<` + batch 逐维校验 + 索引批量化 |
| 3 | `op_host/.../quant_batch_matmul_v3_checker.cpp` | ops-nn | 2 个函数 + 新增 `CheckBatchValidInMxPerGroupMode` |
| 4 | `op_host/.../quant_batch_matmul_v3_checker.h` | ops-nn | 新增函数声明 |
| 5 | `include/blaze/gemm/kernel/kernel_qbmm_mx.h` | ops-tensor | `AddBatchOffset` 新增 pertokenScale/scale GM 指针 batch 偏移 |

## 2.2 aclnn 入口层

### 2.2.1 文件

`op_api/aclnn_quant_matmul_v4.cpp`

### 2.2.2 当前代码

**`CheckDimRange()` (L505-520)：** 参数第一道 gate，只做维度数粗略校验。

```cpp
// L132-135: MX 判定
static inline bool isMx(const aclTensor* scale)
{
    return scale->GetDataType() == op::DataType::DT_FLOAT8_E8M0;
}

// L516-517: gate 检查
size_t expectScaleDim = isMx(scale) ? MX_SCALE_DIM_NUM : 1;  // MX_SCALE_DIM_NUM=3
OP_CHECK_WRONG_DIMENSION(scale, expectScaleDim, return false); // 宏内 != 比较
```

`OP_CHECK_WRONG_DIMENSION` 定义（`common/stub/op_api/.../op_error_check.h` L204）：
```cpp
#define OP_CHECK_WRONG_DIMENSION(tensor, expectedDimNum, retExpr) \
  if (tensor->GetViewShape().GetDimNum() != expectedDimNum) {     \  // != 严格相等
    ...
  }
```

**问题：** `!=` 比较，scale dim≥4 时直接拦截。后续 checker 的 batch 感知校验跑不到。

### 2.2.3 设计

MX scale 永远包含 3 个固定基础维 `(M/K, ceil(K/N/64), 2)`，batch 作为前缀附加。因此维度约束为 `≥3`：

- `<3`：非法，缺 MX 基础维度
- `=3`：无 batch
- `>3`：有 batch（= 3 + batchDimNum）

将 MX 场景的严格相等 `!=` 替换为最小维度检查 `<`：

```cpp
// 改动后
if (isMx(scale)) {
    OP_CHECK_MIN_DIM(scale, MX_SCALE_DIM_NUM, return false);  // < 3 报错，≥3 放行
} else {
    OP_CHECK_WRONG_DIMENSION(scale, 1, return false);          // 非MX保持 !=1
}
```

无需约束上界：x1/out 在同函数内已有 `OP_CHECK_MAX_DIM` 限制 ≤6D（L514-515），且后续 checker 会做 `scaleBatchDim == xBatchDim` 严格对齐，x1≤6 隐含 scale≤7。

`OP_CHECK_MIN_DIM` 定义（`op_error_check.h`）：
```cpp
#define OP_CHECK_MIN_DIM(tensor, minDim, retExpr) \
  if (tensor->GetViewShape().GetDimNum() < static_cast<size_t>(minDim)) { ...
```

**这一层只做粗筛的原因**：`CheckDimRange` 只能拿到 tensor 指针，没有 batch 模式信息（`isPerblock`/`isMxPerGroup`）和 pertokenScale，精细的 batch 逐维校验留给后续 checker 层。

**`MxScaleContiguousProcess()` (L1599-1636)：** 无需改动。已使用 `dimNum-1/dimNum-2/dimNum-3/dimNum-4...` 相对索引，天然兼容 batch 前缀。

### 2.2.4 向后兼容

| 场景 | dim | 旧 `!=3` | 新 `<3` |
|------|-----|---------|---------|
| MX 无batch | 3 | 通过 | 通过 |
| MX 1层batch | 4 | **拒绝** | 通过 |
| MX 2层batch | 5 | **拒绝** | 通过 |
| MX 4层batch | 7 | **拒绝** | 通过 |
| MX 非法 | <3 | 拒绝 | 拒绝 |
| 非MX | 1 | 通过 | 通过（走 else 分支） |

## 2.3 Checker 层

### 2.3.1 概述

**文件**：`op_api/quant_matmul_checker.cpp`

**位置**：aclnn 入口 `CheckDimRange` 粗筛放行后执行，负责 shape / dtype / dim 值的精细校验。

**涉及 MX 的函数**（共 5 个）：

| 函数 | 职责 |
|------|------|
| `CheckMxScaleDimRange` | scale 维度数 + batch 逐维校验 |
| `CheckDimValueMicroScaling` | M/K/N/Last 各维值与 x1/x2 对齐 |
| `InferGroupSizeM` | 从 scale 维度反推 groupSizeM |
| `InferGroupSizeK` | 从 scale 维度反推 groupSizeK |
| `InferGroupSizeN` | 从 scale 维度反推 groupSizeN |

**关键成员变量**（由 `Init()` L319-322 赋值）：

| 成员 | 含义 |
|------|------|
| `x1_` / `x2_` | 输入 tensor |
| `x1Scale_` | pertokenScale（x1 的预量化 scale） |
| `x2Scale_` | scale（x2 的预量化 scale） |
| `transposeX1_` / `transposeX2_` | 转置标志 |
| `x1MDim_` / `x1KDim_` / `x2NDim_` / `x2KDim_` | 各维度值（从 x1/x2 最后两维提取） |

### 2.3.2 CheckMxScaleDimRange（维度数校验）

**当前代码 (L977-996)：**
```cpp
bool QuantMatmulChecker::CheckMxScaleDimRange(size_t x1ScaleDim, size_t x2ScaleDim) const
{
    if (x1ScaleDim != MX_SCALE_DIM) {   // != 严格相等 → 拒绝 >3D
        ...error...
    }
    if (x2ScaleDim != MX_SCALE_DIM) {   // != 严格相等 → 拒绝 >3D
        ...error...
    }
    return true;
}
```

**设计：** `!=` → `<`，并新增 batch 维数与值的逐维匹配。

```cpp
bool QuantMatmulChecker::CheckMxScaleDimRange(size_t x1ScaleDim, size_t x2ScaleDim) const
{
    if (x1ScaleDim < MX_SCALE_DIM) {
        OP_LOGE_FOR_INVALID_SHAPEDIM_WITH_REASON(
            "aclnnQuantMatmulWeightNzGetWorkspaceSize", GetX1ScaleName().c_str(),
            FormatString("%zuD", x1ScaleDim).c_str(),
            FormatString("when the quantization mode is mx, the shape dim of %s must be at least %zuD",
                GetX1ScaleName().c_str(), MX_SCALE_DIM).c_str());
        return false;
    }
    if (x2ScaleDim < MX_SCALE_DIM) {
        OP_LOGE_FOR_INVALID_SHAPEDIM_WITH_REASON(
            "aclnnQuantMatmulWeightNzGetWorkspaceSize", GetX2ScaleName().c_str(),
            FormatString("%zuD", x2ScaleDim).c_str(),
            FormatString("when the quantization mode is mx, the shape dim of %s must be at least %zuD",
                GetX2ScaleName().c_str(), MX_SCALE_DIM).c_str());
        return false;
    }

    // batch 维数对齐
    size_t x1DimNum = x1_->GetViewShape().GetDimNum();
    size_t x2DimNum = x2_->GetViewShape().GetDimNum();
    size_t x1BatchDimNum = x1ScaleDim - MX_SCALE_DIM;
    size_t x2BatchDimNum = x2ScaleDim - MX_SCALE_DIM;
    size_t x1InputBatchDimNum = (x1DimNum > 2) ? (x1DimNum - 2) : 0;
    size_t x2InputBatchDimNum = (x2DimNum > 2) ? (x2DimNum - 2) : 0;

    CHECK_RET(x1BatchDimNum == x1InputBatchDimNum, false);
    CHECK_RET(x2BatchDimNum == x2InputBatchDimNum, false);

    // 逐 batch 维值匹配
    const auto& x1Shape = x1_->GetViewShape();
    const auto& x2Shape = x2_->GetViewShape();
    const auto& x1ScaleShape = x1Scale_->GetViewShape();
    const auto& x2ScaleShape = x2Scale_->GetViewShape();
    for (size_t i = 0; i < x1BatchDimNum; ++i) {
        CHECK_RET(x1ScaleShape.GetDim(i) == x1Shape.GetDim(i), false);
    }
    for (size_t i = 0; i < x2BatchDimNum; ++i) {
        CHECK_RET(x2ScaleShape.GetDim(i) == x2Shape.GetDim(i), false);
    }
    return true;
}
```

**说明：**
- `x1ScaleDim` / `x2ScaleDim` 由调用方传入（已通过 `GetDimNum()` 获取）
- `x1_` / `x2_` / `x1Scale_` / `x2Scale_` 为类成员变量（`Init()` L319-322 赋值）
- `MX_SCALE_DIM = 3`（L39），`GetX1ScaleName()` / `GetX2ScaleName()` 返回 `"pertokenScale"` / `"scale"`（L388-402）
- `CHECK_RET(cond, false)` 为内部一致性校验宏，batch 值不匹配时返回 false 并触发上层错误处理
- 维数对齐公式：scale 去掉 MX 固定 3 维 = x1/x2 去掉最后 2 维（M,K 或 K,N），两边 batch 维数必须相等

### 2.3.3 CheckDimValueMicroScaling（M/K/N/Last 值校验）

**当前代码 (L475-511)：** 维度索引硬编码，无 batch 感知。

```cpp
// L477-480: 硬编码索引
auto x1ScaleMDimIndex = transposeX1_ ? 1 : 0;
auto x1ScaleKDimIndex = transposeX1_ ? 0 : 1;
auto x2ScaleNDimIndex = transposeX2_ ? 0 : 1;
auto x2ScaleKDimIndex = transposeX2_ ? 1 : 0;

// L510-511: 硬编码最后一维位置
x1Scale_->GetViewShape().GetDim(MX_SCALE_DIM - 1)   // MX_SCALE_DIM-1 = 2
x2Scale_->GetViewShape().GetDim(MX_SCALE_DIM - 1)
```

**设计：** 索引改为 `batchDimNum + offset`，最后一维改为 `dimNum - 1`。

```cpp
bool QuantMatmulChecker::CheckDimValueMicroScaling() const
{
    auto x1ScaleDimNum = x1Scale_->GetViewShape().GetDimNum();
    auto x2ScaleDimNum = x2Scale_->GetViewShape().GetDimNum();
    size_t x1BatchDimNum = x1ScaleDimNum - MX_SCALE_DIM;
    size_t x2BatchDimNum = x2ScaleDimNum - MX_SCALE_DIM;

    auto x1ScaleMDimIndex = x1BatchDimNum + (transposeX1_ ? 1 : 0);
    auto x1ScaleKDimIndex = x1BatchDimNum + (transposeX1_ ? 0 : 1);
    auto x2ScaleNDimIndex = x2BatchDimNum + (transposeX2_ ? 0 : 1);
    auto x2ScaleKDimIndex = x2BatchDimNum + (transposeX2_ ? 1 : 0);
    auto x1ScaleMDim = x1Scale_->GetViewShape().GetDim(x1ScaleMDimIndex);
    auto x1ScaleKDim = x1Scale_->GetViewShape().GetDim(x1ScaleKDimIndex);
    auto x2ScaleNDim = x2Scale_->GetViewShape().GetDim(x2ScaleNDimIndex);
    auto x2ScaleKDim = x2Scale_->GetViewShape().GetDim(x2ScaleKDimIndex);

    // shape里有1时,x和scale的转置可以不一致,放开转置一致性校验
    bool x1ScaleHasOne = (x1ScaleMDim == 1 && x1ScaleKDim == x1MDim_) || (x1ScaleMDim == x1MDim_ && x1ScaleKDim == 1) ||
                         (x1ScaleMDim == 1 && x1ScaleKDim == CeilDiv(x1KDim_, MXFP_DIVISOR_SIZE)) ||
                         (x1ScaleMDim == CeilDiv(x1KDim_, MXFP_DIVISOR_SIZE) && x1ScaleKDim == 1);
    bool x2ScaleHasOne = (x2ScaleNDim == 1 && x2ScaleKDim == x2NDim_) || (x2ScaleNDim == x2NDim_ && x2ScaleKDim == 1) ||
                         (x2ScaleNDim == 1 && x2ScaleKDim == CeilDiv(x2KDim_, MXFP_DIVISOR_SIZE)) ||
                         (x2ScaleNDim == CeilDiv(x2KDim_, MXFP_DIVISOR_SIZE) && x2ScaleKDim == 1);

    if ((!x1ScaleHasOne && x1ScaleMDim != x1MDim_) || (!x2ScaleHasOne && x2ScaleNDim != x2NDim_)) {
        OP_LOGE_FOR_INVALID_VALUES_WITH_REASON("aclnnQuantMatmulWeightNzGetWorkspaceSize",
            FormatString("x1 M, %s M, x2 N, %s N", GetX1ScaleName().c_str(), GetX2ScaleName().c_str()).c_str(),
            FormatString("%ld, %ld, %ld, %ld", x1MDim_, x1ScaleMDim, x2NDim_, x2ScaleNDim).c_str(),
            FormatString("when the quantization mode is mx, the M dimension of x1 and %s must be equal, and the N dimension "
                "of x2 and %s must be equal", GetX1ScaleName().c_str(), GetX2ScaleName().c_str()).c_str());
        return false;
    }
    if ((!x1ScaleHasOne && (CeilDiv(x1KDim_, MXFP_DIVISOR_SIZE) != x1ScaleKDim)) ||
        (!x2ScaleHasOne && (CeilDiv(x2KDim_, MXFP_DIVISOR_SIZE) != x2ScaleKDim))) {
        OP_LOGE_FOR_INVALID_VALUES_WITH_REASON("aclnnQuantMatmulWeightNzGetWorkspaceSize",
            FormatString("x1 K, %s K, x2 K, %s K", GetX1ScaleName().c_str(), GetX2ScaleName().c_str()).c_str(),
            FormatString("%ld, %ld, %ld, %ld", x1KDim_, x1ScaleKDim, x2KDim_, x2ScaleKDim).c_str(),
            FormatString("when the quantization mode is mx, the K dimension of %s must be equal to the K dimension of x1 "
                "ceildivided by 64, and the K dimension of %s must be equal to the K dimension of x2 ceildivided by 64",
                GetX1ScaleName().c_str(), GetX2ScaleName().c_str()).c_str());
        return false;
    }

    // 最后一维: 从固定位置 MX_SCALE_DIM-1 (=2) 改为动态 dimNum-1
    if (x1Scale_->GetViewShape().GetDim(x1ScaleDimNum - 1) != MXFP_MULTI_BASE_SIZE ||
        x2Scale_->GetViewShape().GetDim(x2ScaleDimNum - 1) != MXFP_MULTI_BASE_SIZE) {
        OP_LOGE_FOR_INVALID_VALUES_WITH_REASON("aclnnQuantMatmulWeightNzGetWorkspaceSize",
            FormatString("%s last dimension, %s last dimension", GetX1ScaleName().c_str(), GetX2ScaleName().c_str())
                .c_str(),
            FormatString("%ld, %ld", x1Scale_->GetViewShape().GetDim(x1ScaleDimNum - 1),
                x2Scale_->GetViewShape().GetDim(x2ScaleDimNum - 1)).c_str(),
            FormatString("when the quantization mode is mx, the last dimension of %s and %s must be 2",
                GetX1ScaleName().c_str(), GetX2ScaleName().c_str()).c_str());
        return false;
    }

    if (IsFp4Input(x1_, x2_)) {
        CHECK_RET(CheckMXFP4FP8ParamsNDOrNZ(), false);
    }
    return true;
}
```

**说明：**
- 仅改动索引计算（L477-480）和最后一维取值（L510-511），其余值比较逻辑不变
- `x1ScaleHasOne` / `x2ScaleHasOne` 等比较用的是索引取出的**值**，索引变了值自动跟随
- batch 不存在时 `batchDimNum = 0`，索引退化为原逻辑

### 2.3.4 InferGroupSizeM / InferGroupSizeK / InferGroupSizeN

**当前代码：** 硬编码 scale 维度索引，同上面的模式。

```cpp
// InferGroupSizeM L620:
scaleSizeM = x1Scale->GetViewShape().GetDim(transX1 ? 1 : 0);

// InferGroupSizeK L638:

// InferGroupSizeN L656:
```

**设计：** MX 分支索引统一加 `batchDimNum` 偏移。非 MX 分支已用相对索引（`xScaleDimNum - 1`），无需改动。

```cpp
// 改动后
size_t x1ScaleBatchDimNum = x1ScaleDimNum - MX_SCALE_DIM;
scaleSizeM = x1Scale->GetViewShape().GetDim(x1ScaleBatchDimNum + (transX1 ? 1 : 0));
```

**InferGroupSizeK (L638)：**
```cpp
// 改动前
scaleSizeK = x1Scale->GetViewShape().GetDim(transX1 ? 0 : 1) * MICRO_SCALING_ALIGN_NUM;

// 改动后
size_t x1ScaleBatchDimNum = x1ScaleDimNum - MX_SCALE_DIM;
scaleSizeK = x1Scale->GetViewShape().GetDim(x1ScaleBatchDimNum + (transX1 ? 0 : 1)) * MICRO_SCALING_ALIGN_NUM;
```

**InferGroupSizeN (L656-658)：**

```cpp
// 改动前
```

- `x1ScaleDimNum` / `x2ScaleDimNum` 已在上文由 `GetDimNum()` 获取

## 2.4 Tiling Checker 层

### 2.4.1 概述

**文件：**
- `op_host/op_tiling/arch35/quant_batch_matmul_v3_checker.cpp`
- `op_host/op_tiling/arch35/quant_batch_matmul_v3_checker.h`

**位置：** Tiling 计算前的最后一道校验，在 api checker（2.3 节）之后执行。负责 shape / dtype / dim 值的最终校验。

**涉及 MX 的函数（共 4 个）：**

| 函数 | 职责 |
|------|------|
| `MxPertokenScaleShapeCheck` | pertokenScale 维度数 + M/K/Last 值校验 |
| `MxScaleShapeCheck` | scale 维度数 + K/N/Last 值校验 |
| `CheckInputValidInMxPerGroupMode` | MX per-group 模式综合校验（签名需扩展） |
| **新增** `CheckBatchValidInMxPerGroupMode` | MX 模式 batch 逐维匹配 |

**关键成员/参数：**

| 名称 | 含义 |
|------|------|
| `inputParams_.transA` / `transB` | 转置标志 |
| `inputParams_.mSize` / `nSize` / `kSize` | 矩阵维度值（从 x1/x2 最后两维提取，已去 batch） |

| `inputParams_.isMxPerGroup` | 是否 MX per-group 模式 |

**校验宏：** 使用 `OP_TILING_CHECK(condition, error_action, return false)`，与 api checker 的 `CHECK_RET` 不同——它支持在报错时执行自定义错误日志操作。

### 2.4.4 新增 CheckBatchValidInMxPerGroupMode

MX 模式新增 batch 逐维匹配函数，对照 Perblock 路径已有的 `CheckBatchValidInPerblockMode` 模式：

```cpp
bool QuantBatchMatmulV3Checker::CheckBatchValidInMxPerGroupMode(
    const gert::Shape& scaleShape, const gert::Shape& pertoken,
    const gert::Shape& x1Shape, const gert::Shape& x2Shape) const
{
    size_t scaleBatchDimNum = scaleShape.GetDimNum() - SCALE_THREE_DIM;
    size_t pertokenBatchDimNum = pertoken.GetDimNum() - SCALE_THREE_DIM;
    size_t x1BatchDimNum = x1Shape.GetDimNum() > 2 ? x1Shape.GetDimNum() - 2 : 0;
    size_t x2BatchDimNum = x2Shape.GetDimNum() > 2 ? x2Shape.GetDimNum() - 2 : 0;

    // batch 维数匹配
    OP_TILING_CHECK(scaleBatchDimNum == x2BatchDimNum, ...);
    OP_TILING_CHECK(pertokenBatchDimNum == x1BatchDimNum, ...);

    // 逐维值匹配
    for (size_t i = 0; i < scaleBatchDimNum; i++)
        OP_TILING_CHECK(scaleShape.GetDim(i) == x2Shape.GetDim(i), ...);
    for (size_t i = 0; i < pertokenBatchDimNum; i++)
        OP_TILING_CHECK(pertoken.GetDim(i) == x1Shape.GetDim(i), ...);

    return true;
}
```

## 2.5 Kernel 层

### 2.5.1 Cmct 内核

**文件：** `matmul/common/cmct/kernel/kernel_qbmm_mx.h`

**当前代码 `AddBatchOffset()` (L282-305)：** 只处理 A/B/C/Bias 的 batch 偏移，**无 scale 的 batch 偏移**。

**设计：** 在 `AddBatchOffset` 中新增 X1SCALE 和 X2SCALE 的 batch stride：

```cpp
// 在 A 偏移之后插入：
Get<QuantBatchMatmul::IDX_X1SCALE_OFFSET>(blockOffset_) +=
    batchAOffset_ * (params.problemShape.m *
        CeilDiv(params.problemShape.k, MXFP_DIVISOR_SIZE) * MXFP_MULTI_BASE_SIZE);

// 在 B 偏移之后、C 偏移之前插入：
Get<QuantBatchMatmul::IDX_X2SCALE_OFFSET>(blockOffset_) +=
    batchBOffset_ * (params.problemShape.n *
        CeilDiv(params.problemShape.k, MXFP_DIVISOR_SIZE) * MXFP_MULTI_BASE_SIZE);
```

- `MXFP_DIVISOR_SIZE = 64`，`MXFP_MULTI_BASE_SIZE = 2`
- `batchAOffset_` / `batchBOffset_`：Cmct 框架 batch 迭代计数器
- X1SCALE (pertokenScale) 偏移跟随 batchA，X2SCALE (scale) 偏移跟随 batchB

### 2.5.2 Blaze 内核

Blaze 路径 `GemmUniversal` 为外部预编译库。当前 wrapper `qbmm_mx_tensor_api_blaze.h` 将 scale 作为单一 `GM_ADDR` 传入。需确认 Blaze 库版本是否已包含等效 batch stride 逻辑；若不支持，需在 wrapper 层或 Blaze 侧补充。

### 2.5.3 Kernel Wrapper

**文件：** `qbmm_mx_tensor_api_blaze.h` / `qbmm_mx_basic_api_cmct.h`

两个 wrapper 传参结构 `{aGM, bGM, cGM, bias, perTokenScale, scale}` 不变，无需改动。
