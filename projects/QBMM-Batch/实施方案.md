# 1 算子需求

## 1.1 设计约束

- 运行环境：A5（Ascend 950），Blaze TensorAPI 路径
- 调用方式：单算子 `aclnnQuantMatmulWeightNz`
- 适用算子：`quantBatchMatmulV3`，MX 全量化路径
- 设计原则：简洁、最小改动
- 涉及仓：
  - `ops-nn`（算子实现，校验层修改）
  - `ops-tensor`（Blaze TensorAPI 库，kernel 层修改）

## 1.2 需求描述

### 1.2.1 功能描述

MX 全量化场景，scaleX1/scaleX2 增加 batch 维度支持：

| | 变更前 | 变更后 |
|---|--------|--------|
| scaleX1 shape | `(m, ceil(K/64), 2)` | `(batchA, m, ceil(K/64), 2)` |
| scaleX2 shape | `(ceil(K/64), n, 2)` | `(batchB, ceil(K/64), n, 2)` |

batch 维度数与 x1/x2 的 batch 维度数一致，各维值逐维匹配。

### 1.2.2 适用范围

| 量化类型 | x1 dtype | x2 dtype | scale dtype | x1/x2 维度 | 涉及？ |
|---------|----------|----------|-------------|-----------|--------|
| mx 全量化 | F8_E4M3FN / F8_E5M2 | F8_E4M3FN / F8_E5M2 | F8_E8M0 | 3-6D | ✅ |
| mx 全量化 | F4_E2M1 | F4_E2M1 | F8_E8M0 | 3-6D | ✅ |
| mx A8W4 | F8_E4M3FN | F4_E2M1 (NZ) | F8_E8M0 | x1=2D | ❌ 不在范围 |
| mx A8W4 | F8_E4M3FN | FLOAT32 (ND) | F8_E8M0 | x1=2D | ❌ 不在范围 |

MX 全量化强制带 batch：x1/x2 必须 ≥ 3D（含 ≥1 层 batch），scale 对应附加 batch 前缀（scale dim ≥ 4）。x1/x2 为 2D（无 batch）不再支持，接口层直接拒绝。

### 1.2.3 精度要求

精度继承原算子 MX 量化标准，满足 mxfp8/mxfp4 精度验收标准。

# 2 算子设计

## 2.1 总体设计

### 2.1.1 核心思想

Scale 维度模型从固定 3 维改为 `batchPrefix + MX3D`：

```
Scale Shape:  [batch_0, ..., batch_N] + [M/ceil(k/64), ceil(k/64)/N, 2]
               ← batchDimNum →           ← MX 固定 3 维 →
               batchDimNum = totalDimNum - 3
```

所有访问 M/K/N/Last 维度的索引统一为 `batchDimNum + offset`。接口层强制带 batch，`batchDimNum ≥ 1`（`batchDimNum = totalDimNum - 3`，固定 3 维为 MX 基础维）。

### 2.1.2 与 GMM 的 batch 差异

| | GMM (grouped_matmul_finalize_routing) | QBMM V3 |
|---|------|------|
| batch 本质 | experts 分组，每组 M/N/K 不同 | MatMul 批量，所有 batch 共享 M/N/K |
| x 维度 | 始终 2D `(M, K)` | 3-6D `(batch, M, K)` |
| scale batch 来源 | groupList（experts 个数） | x1/x2 的 batch 维 |
| tiling | 按组独立计算 | 统一，batch 仅作计算量乘数 |
| 需新增 tiling 字段？ | 不需要（复用 groupList） | **不需要**（复用 batchA1-4 / batchB1-4） |

QBMM V3 的 scale batch 信息在 `QuantBatchMatmulV3BasicAPIDataParams` 中已存在（`batchA1-4` / `batchB1-4`），kernel 层直接用现有 batch 维计算 scale stride，不需要新增 tiling 字段。

### 2.1.3 A5 调用链分析（仅 DAV_3510）

- x2=ND → `aclnnQuantMatmulV5`

两条路径最终都调 `l0op::QuantBatchMatmulV3()`，共享同一套 checker / tiling / kernel。

## 2.2 torch 层

### 2.2.1 文件

`op-plugin/op_plugin/ops/opapi/QuantMatmulKernelNpuOpApi.cpp`

### 2.2.2 调用路由

torch 层路由（L295-303）对 MX FP8×FP8 的分流：

### 2.2.3 transpose 校验

L259-275 `need_check_trans` 对 MX (FLOAT8_E8M0) 为 true，需要正确计算 `dim_x1_scale` / `dim_x2_scale`：

```cpp
// L269-275
if (pertoken_scale_dtype_real != aclDataType::ACL_FLOAT8_E8M0) {
    dim_x1_scale = pertoken_scale_real.dim() - 2;   // Perblock：尾巴 2 维
    dim_x2_scale = scale.dim() - 2;
} else {
    dim_x1_scale = pertoken_scale_real.dim() - 3;  // MX 尾巴 3 维
    dim_x2_scale = scale.dim() - 3;
}
```

`dim - 3` 动态适应任意 batch 层数（减去 MX 固定 3 维得到 batch 维数）。接口层强制带 batch，`dim ≥ 4`，`dim-3 ≥ 1`。

## 2.3 aclnn 入口层

### 2.3.1 文件

`quant_batch_matmul_v3/op_api/aclnn_quant_matmul_v4.cpp`

该文件包含三个 aclnn 入口（V3/V4/WeightNz），MX FP8×FP8 NZ 走 WeightNz 入口（L2135），非 A8W4 路径调用 `CheckDimRange`（L505）。

### 2.3.2 当前代码

**`CheckDimRange()` (L505-520)：** 参数第一道 gate，只做维度数粗略校验。

```cpp
// L132-135: MX 判定
static inline bool isMx(const aclTensor* scale)
{
    return scale->GetDataType() == op::DataType::DT_FLOAT8_E8M0;
}

// L516-517: gate 检查
size_t expectScaleDim = isMx(scale) ? MX_SCALE_DIM_NUM : 1;  // MX_SCALE_DIM_NUM=4
OP_CHECK_WRONG_DIMENSION(scale, expectScaleDim, return false); // 宏内 != 比较
```

`OP_CHECK_WRONG_DIMENSION` 定义（`common/stub/op_api/.../op_error_check.h` L204）：
```cpp
#define OP_CHECK_WRONG_DIMENSION(tensor, expectedDimNum, retExpr) \
  if (tensor->GetViewShape().GetDimNum() != expectedDimNum) {     \  // != 严格相等
    ...
  }
```

**问题：** `!=` 比较，scale dim≥4（带 batch）时直接拦截。后续 checker 的 batch 感知校验跑不到。

### 2.3.3 设计

MX scale 由 3 个固定基础维 `(M/K, ceil(K/N/64), 2)` + batch 前缀构成，且接口层强制必须带 batch（至少 1 层）。因此维度约束为 `≥4`：

- `<4`：非法，拒绝（含 dim=3 的无 batch 场景，已不再支持）
- `=4`：1 层 batch
- `>4`：多层 batch（= 3 + batchDimNum，batchDimNum ≥ 1）

将 MX 场景的严格相等 `!=` 替换为最小维度检查 `<`，下限由 3 提升为 4（`MX_SCALE_DIM_NUM` 值由 3 改为 4）：

```cpp
// 改动后
if (isMx(scale)) {
    OP_CHECK_MIN_DIM(scale, MX_SCALE_DIM_NUM, return false);  // < 4 报错，≥4 放行
} else {
    OP_CHECK_WRONG_DIMENSION(scale, 1, return false);          // 非MX保持 !=1
}
```

无需约束上界：x1/out 在同函数内已有 `OP_CHECK_MAX_DIM` 限制 ≤6D（L514-515），且后续 checker 会做 `scaleBatchDim == xBatchDim` 严格对齐，x1≤6 隐含 scale≤7。

`OP_CHECK_MIN_DIM` 定义（`op_error_check.h`）：
```cpp
#define OP_CHECK_MIN_DIM(tensor, minDim, retExpr) \
  if (tensor->GetViewShape().GetDimNum() < static_cast<size_t>(minDim)) { ...
```

**这一层只做粗筛的原因**：`CheckDimRange` 只能拿到 tensor 指针，没有 batch 模式信息（`isPerblock`/`isMxPerGroup`）和 pertokenScale，精细的 batch 逐维校验留给后续 checker 层。

**`MxScaleContiguousProcess()` (L1599-1636)：** 无需改动。已使用 `dimNum-1/dimNum-2/dimNum-3/dimNum-4...` 相对索引，天然兼容 batch 前缀。

### 2.3.4 维度放行情况

| 场景 | dim | 旧 `!=3` | 新 `<4` |
|------|-----|---------|---------|
| MX 无batch | 3 | 通过 | **拒绝**（不再支持） |
| MX 1层batch | 4 | **拒绝** | 通过 |
| MX 2层batch | 5 | **拒绝** | 通过 |
| MX 4层batch | 7 | **拒绝** | 通过 |
| MX 非法 | <3 | 拒绝 | 拒绝 |
| 非MX | 1 | 通过 | 通过（走 else 分支） |

## 2.4 Checker 层

### 2.4.1 概述

**文件**：`op_api/quant_matmul_checker.cpp`

**位置**：aclnn 入口 `CheckDimRange` 粗筛放行后执行，负责 shape / dtype / dim 值的精细校验。

**涉及 MX 的函数**（共 5 个）：

| 函数 | 职责 |
|------|------|
| `CheckMxScaleDimRange` | scale 维度数 + batch 逐维校验 |
| `CheckDimValueMicroScaling` | M/K/N/Last 各维值与 x1/x2 对齐 |
| `InferGroupSizeM` | 从 scale 维度反推 groupSizeM |
| `InferGroupSizeK` | 从 scale 维度反推 groupSizeK |
| `InferGroupSizeN` | 从 scale 维度反推 groupSizeN |

**关键成员变量**（由 `Init()` L319-322 赋值）：

| 成员 | 含义 |
|------|------|
| `x1_` / `x2_` | 输入 tensor |
| `x1Scale_` | pertokenScale（x1 的预量化 scale） |
| `x2Scale_` | scale（x2 的预量化 scale） |
| `transposeX1_` / `transposeX2_` | 转置标志 |
| `x1MDim_` / `x1KDim_` / `x2NDim_` / `x2KDim_` | 各维度值（从 x1/x2 最后两维提取） |

### 2.4.2 CheckMxScaleDimRange（维度数校验）

**当前代码 (L977-996)：**
```cpp
bool QuantMatmulChecker::CheckMxScaleDimRange(size_t x1ScaleDim, size_t x2ScaleDim) const
{
    if (x1ScaleDim != MX_SCALE_DIM) {   // != 严格相等 → 拒绝 >3D
        ...error...
    }
    if (x2ScaleDim != MX_SCALE_DIM) {   // != 严格相等 → 拒绝 >3D
        ...error...
    }
    return true;
}
```

**设计：** 下限校验从 `!= MX_SCALE_DIM(3)` 改为 `< MX_SCALE_MIN_DIM_WITH_BATCH(4)`（强制带 batch，拒绝 dim=3 无 batch），并新增 batch 维数与值的逐维匹配。注意 batchDimNum 仍按 `scaleDim - MX_SCALE_DIM(3)` 计算（减固定 3 维，不变）。

```cpp
bool QuantMatmulChecker::CheckMxScaleDimRange(size_t x1ScaleDim, size_t x2ScaleDim) const
{
    if (x1ScaleDim < MX_SCALE_MIN_DIM_WITH_BATCH) {
        OP_LOGE_FOR_INVALID_SHAPEDIM_WITH_REASON(
            "aclnnQuantMatmulWeightNzGetWorkspaceSize", GetX1ScaleName().c_str(),
            FormatString("%zuD", x1ScaleDim).c_str(),
            FormatString("when the quantization mode is mx, the shape dim of %s must be at least %zuD",
                GetX1ScaleName().c_str(), MX_SCALE_MIN_DIM_WITH_BATCH).c_str());
        return false;
    }
    if (x2ScaleDim < MX_SCALE_MIN_DIM_WITH_BATCH) {
        OP_LOGE_FOR_INVALID_SHAPEDIM_WITH_REASON(
            "aclnnQuantMatmulWeightNzGetWorkspaceSize", GetX2ScaleName().c_str(),
            FormatString("%zuD", x2ScaleDim).c_str(),
            FormatString("when the quantization mode is mx, the shape dim of %s must be at least %zuD",
                GetX2ScaleName().c_str(), MX_SCALE_MIN_DIM_WITH_BATCH).c_str());
        return false;
    }

    // batch 维数对齐（batchDimNum 仍减固定 3 维）
    size_t x1DimNum = x1_->GetViewShape().GetDimNum();
    size_t x2DimNum = x2_->GetViewShape().GetDimNum();
    size_t x1BatchDimNum = x1ScaleDim - MX_SCALE_DIM;
    size_t x2BatchDimNum = x2ScaleDim - MX_SCALE_DIM;
    size_t x1InputBatchDimNum = (x1DimNum > 2) ? (x1DimNum - 2) : 0;
    size_t x2InputBatchDimNum = (x2DimNum > 2) ? (x2DimNum - 2) : 0;

    CHECK_RET(x1BatchDimNum == x1InputBatchDimNum, false);
    CHECK_RET(x2BatchDimNum == x2InputBatchDimNum, false);

    // 逐 batch 维值匹配
    const auto& x1Shape = x1_->GetViewShape();
    const auto& x2Shape = x2_->GetViewShape();
    const auto& x1ScaleShape = x1Scale_->GetViewShape();
    const auto& x2ScaleShape = x2Scale_->GetViewShape();
    for (size_t i = 0; i < x1BatchDimNum; ++i) {
        CHECK_RET(x1ScaleShape.GetDim(i) == x1Shape.GetDim(i), false);
    }
    for (size_t i = 0; i < x2BatchDimNum; ++i) {
        CHECK_RET(x2ScaleShape.GetDim(i) == x2Shape.GetDim(i), false);
    }
    return true;
}
```

**说明：**
- `x1ScaleDim` / `x2ScaleDim` 由调用方传入（已通过 `GetDimNum()` 获取）
- `x1_` / `x2_` / `x1Scale_` / `x2Scale_` 为类成员变量（`Init()` L319-322 赋值）
- `MX_SCALE_DIM = 3`（L39，MX 固定基础维数）、`MX_SCALE_MIN_DIM_WITH_BATCH = 4`（强制带 batch 的最小维数）；`GetX1ScaleName()` / `GetX2ScaleName()` 返回 `"pertokenScale"` / `"scale"`（L388-402）
- `CHECK_RET(cond, false)` 为内部一致性校验宏，batch 值不匹配时返回 false 并触发上层错误处理
- 维数对齐公式：scale 去掉 MX 固定 3 维 = x1/x2 去掉最后 2 维（M,K 或 K,N），两边 batch 维数必须相等且 ≥ 1

### 2.4.3 CheckDimValueMicroScaling（M/K/N/Last 值校验）

**当前代码 (L475-511)：** 维度索引硬编码，无 batch 感知。

```cpp
// L477-480: 硬编码索引
auto x1ScaleMDimIndex = transposeX1_ ? 1 : 0;
auto x1ScaleKDimIndex = transposeX1_ ? 0 : 1;
auto x2ScaleNDimIndex = transposeX2_ ? 0 : 1;
auto x2ScaleKDimIndex = transposeX2_ ? 1 : 0;

// L510-511: 硬编码最后一维位置
x1Scale_->GetViewShape().GetDim(MX_SCALE_DIM - 1)   // MX_SCALE_DIM-1 = 2
x2Scale_->GetViewShape().GetDim(MX_SCALE_DIM - 1)
```

**设计：** 索引改为 `batchDimNum + offset`，最后一维改为 `dimNum - 1`。

```cpp
bool QuantMatmulChecker::CheckDimValueMicroScaling() const
{
    auto x1ScaleDimNum = x1Scale_->GetViewShape().GetDimNum();
    auto x2ScaleDimNum = x2Scale_->GetViewShape().GetDimNum();
    size_t x1BatchDimNum = x1ScaleDimNum - MX_SCALE_DIM;
    size_t x2BatchDimNum = x2ScaleDimNum - MX_SCALE_DIM;

    auto x1ScaleMDimIndex = x1BatchDimNum + (transposeX1_ ? 1 : 0);
    auto x1ScaleKDimIndex = x1BatchDimNum + (transposeX1_ ? 0 : 1);
    auto x2ScaleNDimIndex = x2BatchDimNum + (transposeX2_ ? 0 : 1);
    auto x2ScaleKDimIndex = x2BatchDimNum + (transposeX2_ ? 1 : 0);
    auto x1ScaleMDim = x1Scale_->GetViewShape().GetDim(x1ScaleMDimIndex);
    auto x1ScaleKDim = x1Scale_->GetViewShape().GetDim(x1ScaleKDimIndex);
    auto x2ScaleNDim = x2Scale_->GetViewShape().GetDim(x2ScaleNDimIndex);
    auto x2ScaleKDim = x2Scale_->GetViewShape().GetDim(x2ScaleKDimIndex);

    // shape里有1时,x和scale的转置可以不一致,放开转置一致性校验
    bool x1ScaleHasOne = (x1ScaleMDim == 1 && x1ScaleKDim == x1MDim_) || (x1ScaleMDim == x1MDim_ && x1ScaleKDim == 1) ||
                         (x1ScaleMDim == 1 && x1ScaleKDim == CeilDiv(x1KDim_, MXFP_DIVISOR_SIZE)) ||
                         (x1ScaleMDim == CeilDiv(x1KDim_, MXFP_DIVISOR_SIZE) && x1ScaleKDim == 1);
    bool x2ScaleHasOne = (x2ScaleNDim == 1 && x2ScaleKDim == x2NDim_) || (x2ScaleNDim == x2NDim_ && x2ScaleKDim == 1) ||
                         (x2ScaleNDim == 1 && x2ScaleKDim == CeilDiv(x2KDim_, MXFP_DIVISOR_SIZE)) ||
                         (x2ScaleNDim == CeilDiv(x2KDim_, MXFP_DIVISOR_SIZE) && x2ScaleKDim == 1);

    if ((!x1ScaleHasOne && x1ScaleMDim != x1MDim_) || (!x2ScaleHasOne && x2ScaleNDim != x2NDim_)) {
        OP_LOGE_FOR_INVALID_VALUES_WITH_REASON("aclnnQuantMatmulWeightNzGetWorkspaceSize",
            FormatString("x1 M, %s M, x2 N, %s N", GetX1ScaleName().c_str(), GetX2ScaleName().c_str()).c_str(),
            FormatString("%ld, %ld, %ld, %ld", x1MDim_, x1ScaleMDim, x2NDim_, x2ScaleNDim).c_str(),
            FormatString("when the quantization mode is mx, the M dimension of x1 and %s must be equal, and the N dimension "
                "of x2 and %s must be equal", GetX1ScaleName().c_str(), GetX2ScaleName().c_str()).c_str());
        return false;
    }
    if ((!x1ScaleHasOne && (CeilDiv(x1KDim_, MXFP_DIVISOR_SIZE) != x1ScaleKDim)) ||
        (!x2ScaleHasOne && (CeilDiv(x2KDim_, MXFP_DIVISOR_SIZE) != x2ScaleKDim))) {
        OP_LOGE_FOR_INVALID_VALUES_WITH_REASON("aclnnQuantMatmulWeightNzGetWorkspaceSize",
            FormatString("x1 K, %s K, x2 K, %s K", GetX1ScaleName().c_str(), GetX2ScaleName().c_str()).c_str(),
            FormatString("%ld, %ld, %ld, %ld", x1KDim_, x1ScaleKDim, x2KDim_, x2ScaleKDim).c_str(),
            FormatString("when the quantization mode is mx, the K dimension of %s must be equal to the K dimension of x1 "
                "ceildivided by 64, and the K dimension of %s must be equal to the K dimension of x2 ceildivided by 64",
                GetX1ScaleName().c_str(), GetX2ScaleName().c_str()).c_str());
        return false;
    }

    // 最后一维: 从固定位置 MX_SCALE_DIM-1 (=2) 改为动态 dimNum-1
    if (x1Scale_->GetViewShape().GetDim(x1ScaleDimNum - 1) != MXFP_MULTI_BASE_SIZE ||
        x2Scale_->GetViewShape().GetDim(x2ScaleDimNum - 1) != MXFP_MULTI_BASE_SIZE) {
        OP_LOGE_FOR_INVALID_VALUES_WITH_REASON("aclnnQuantMatmulWeightNzGetWorkspaceSize",
```

### 2.5.4 新增 CheckBatchValidInMxPerGroupMode

**为什么不能复用 Perblock 的 `CheckBatchValidInPerblockMode`：**

Perblock 模式下 scale 的 shape **完全等于** x1/x2 的 shape（尾巴都是 2 维 `M,K` / `K,N`），batch 维数公式都是 `dim - 2`：

```
Perblock：
x2:      (B1, B2, K, N)      → batch = 4-2 = 2
scale:   (B1, B2, K, N)      → batch = 4-2 = 2   ← 公式相同
```

MX 模式下 scale 的尾巴是**固定 3 维** `(M/ceil(K/64), ceil(K/64)/N, 2)`，而 x1/x2 的尾巴仍然是 2 维：

```
MX：
x2:      (B1, B2,    K,    N)          4D  → batch = 4-2 = 2
scale:   (B1, B2, ceil(K/64), N, 2)    5D  → batch = 5-3 = 2   ← 公式不同！
```

如果用 Perblock 的 `5-2=3`，会把 `ceil(K/64)` 也算进 batch，导致 batch 维数多算，校验跑偏。

**因为公式差 1（`-3` vs `-2`），所以必须写独立函数。核心逻辑与 Perblock 模板完全一致，仅 batch 维数计算公式不同。**

**完整代码：**

```cpp
bool QuantBatchMatmulV3Checker::CheckBatchValidInMxPerGroupMode(
    const gert::Shape& scaleShape,    // scaleX2
    const gert::Shape& pertoken,      // scaleX1 (=pertokenScale)
    const gert::Shape& x1Shape,
    const gert::Shape& x2Shape) const
{
    // ① 计算各 tensor 的 batch 维数
    //    scale/pertoken：去掉 MX 固定 3 维尾巴 → batch = dim - 3
    //    x1/x2：去掉 MatMul 最后 2 维 (M,K)/(K,N) → batch = dim - 2
    size_t scaleBatchDimNum = scaleShape.GetDimNum() - SCALE_THREE_DIM;
    size_t pertokenBatchDimNum = pertoken.GetDimNum() - SCALE_THREE_DIM;
    size_t x1BatchDimNum = x1Shape.GetDimNum() > DIM_NUM_TWO ? x1Shape.GetDimNum() - DIM_NUM_TWO : 0;
    size_t x2BatchDimNum = x2Shape.GetDimNum() > DIM_NUM_TWO ? x2Shape.GetDimNum() - DIM_NUM_TWO : 0;

    // ② batch 维数对齐，必须精确匹配
    OP_TILING_CHECK(
        scaleBatchDimNum != x2BatchDimNum,
        OP_LOGE_FOR_INVALID_VALUES_WITH_REASON(
            inputParams_.opName, "scaleBatchDim, x2BatchDim",
            FormatString("%zu, %zu", scaleBatchDimNum, x2BatchDimNum).c_str(),
            "In mx quantification, scale batch dimension count[%zu] should be equal to "
            "x2 batch dimension count[%zu].", scaleBatchDimNum, x2BatchDimNum),
        return false);

    OP_TILING_CHECK(
        pertokenBatchDimNum != x1BatchDimNum,
        OP_LOGE_FOR_INVALID_VALUES_WITH_REASON(
            inputParams_.opName, "pertokenBatchDim, x1BatchDim",
            FormatString("%zu, %zu", pertokenBatchDimNum, x1BatchDimNum).c_str(),
            "In mx quantification, pertokenScale batch dimension count[%zu] should be equal to "
            "x1 batch dimension count[%zu].", pertokenBatchDimNum, x1BatchDimNum),
        return false);

    // ③ 逐 batch 维值匹配
    for (size_t i = 0; i < scaleBatchDimNum; ++i) {
        OP_TILING_CHECK(
            scaleShape.GetDim(i) != x2Shape.GetDim(i),
            OP_LOGE_FOR_INVALID_VALUES_WITH_REASON(
                inputParams_.opName, "dimIndex, x2Batch, scaleBatch",
                FormatString("%zu, %ld, %ld", i, x2Shape.GetDim(i), scaleShape.GetDim(i)).c_str(),
                "In mx quantification, x2 batch and scale batch should be equal, "
                "but at dimension %zu, x2 batch: %ld, scale batch: %ld.",
                i, x2Shape.GetDim(i), scaleShape.GetDim(i)),
            return false);
    }

    for (size_t i = 0; i < pertokenBatchDimNum; ++i) {
        OP_TILING_CHECK(
            pertoken.GetDim(i) != x1Shape.GetDim(i),
            OP_LOGE_FOR_INVALID_VALUES_WITH_REASON(
                inputParams_.opName, "dimIndex, x1Batch, pertokenBatch",
                FormatString("%zu, %ld, %ld", i, x1Shape.GetDim(i), pertoken.GetDim(i)).c_str(),
                "In mx quantification, x1 batch and pertokenScale batch should be equal, "
                "but at dimension %zu, x1 batch: %ld, pertokenScale batch: %ld.",
                i, x1Shape.GetDim(i), pertoken.GetDim(i)),
            return false);
    }
    return true;
}
```

**示例验证：**

```
x1 = (2, 8, 64, 128)            → 4D: B1=2, B2=8, M=64, K=128
x2 = (2, 8, 128, 256)           → 4D: B1=2, B2=8, K=128, N=256
scaleX1 = (2, 8, 64, 2, 2)      → 5D: B1=2, B2=8, M=64, ceil(K/64)=2, last=2
scaleX2 = (2, 8, 2, 256, 2)     → 5D: B1=2, B2=8, ceil(K/64)=2, N=256, last=2

scaleBatchDimNum    = 5 - 3 = 2 → B1, B2
x2BatchDimNum       = 4 - 2 = 2 → B1, B2   ✅ 对齐

逐维：scaleShape[0]=2 == x2Shape[0]=2 ✅
      scaleShape[1]=8 == x2Shape[1]=8 ✅
```

## 2.6 Kernel 层

### 2.6.1 背景

QBMM 的 MX kernel 由编译期宏 `IS_BLAZE` 二选一，scale batch 偏移需在两条路径对称落地：

- **Blaze 路径**（CANN≥9.1，`IS_BLAZE=true`）：ops-tensor 仓 `include/blaze/gemm/kernel/kernel_qbmm_mx.h`，改动点 #5，详见 2.6.2-2.6.6。
- **CMCT 路径**（CANN 9.0，`IS_BLAZE=false`）：ops-nn 仓 `matmul/common/cmct/kernel/kernel_qbmm_mx.h`，改动点 #5b，详见 2.6.7。

**代码证明 — CANN 9.0 才走 CMCT**（ops-nn 仓 `matmul/quant_batch_matmul_v3/op_kernel/arch35/quant_batch_matmul_v3.cpp`）：

`IS_BLAZE` 宏由 asc-devkit（CANN）版本决定，L16-20：

```cpp

#define IS_BLAZE true
#else                                               // CANN 9.0.0 (MINOR==0) → false
#define IS_BLAZE false
#endif
```

MX（E8M0 scale）kernel 头的选择，L37-44：

```cpp

#include "tensor_api/tensor.h"
#include "qbmm_mx_tensor_api_blaze.h"                  // → Blaze 路径 (#5)
#elif (ORIG_DTYPE_SCALE == DT_FLOAT8_E8M0)             // E8M0 但 IS_BLAZE=false，即 CANN 9.0
#include "qbmm_mx_basic_api_cmct.h"                    // → CMCT 路径 (#5b)
#else
#include "qbmm_cube_basic_api_cmct.h"
#endif
```

可见：MX E8M0 场景下，`IS_BLAZE=false`（CANN 9.0.0，`ASC_DEVKIT_MINOR==0`）走 `qbmm_mx_basic_api_cmct.h`（CMCT 路径 #5b）；`IS_BLAZE=true`（CANN≥9.1）走 `qbmm_mx_tensor_api_blaze.h`（Blaze 路径 #5）。该宏无 build.sh/CLI 开关可覆盖，只能由 CANN 版本决定。

> 两条路径的 `AddBatchOffset` 当前都已为 x1/x2/out/bias 做 batch 偏移，唯独 pertokenScale/scale 缺失。本设计在两份内核中实施等效改动（`batchOffset × 单batch元素数`），公式相同（pertokenScale=M×ceil(K/64)×2、scale=N×ceil(K/64)×2），fp8/fp4 均覆盖。两份逻辑必须同步——任一份漂移会静默读错 scale、不报编译错。

### 2.6.2 核心数据结构（L134-150）

**6 个 GM 指针**（L137-142），`ProcessWithBatch` 每轮 batch iteration 通过 `AddBatchOffset` 对它们做偏移：

```cpp
__gm__ AType* aGmAddr_;                         // x1
__gm__ BType* bGmAddr_;                         // x2
__gm__ CType* cGmAddr_;                         // out
__gm__ BiasType* biasGmAddr_ = nullptr;         // bias（可选）
__gm__ fp8_e8m0_t* pertokenScaleGmAddr_;        // scaleX1 (=pertokenScale)
__gm__ fp8_e8m0_t* scaleGmAddr_;                // scaleX2 (=scale)
```

**3 个 batch 偏移计数器**（L145-147），由 `ProcessWithBatch` 4 层循环维护：

```cpp
uint64_t batchCOffset_{0};
uint64_t batchAOffset_{0};   // 每轮 iteration 递增，经过 broadcast 比率修正
uint64_t batchBOffset_{0};
```

**`batchAOffset_` 和 `batchBOffset_` 是否相同？**

不一定。取决于是否存在 batch broadcast：

```
x1=(3, M, K)  x2=(1, K, N)  → B 在 batch 维广播

multiA4C4 = 3/3 = 1 → batchAOffset_ 每轮 +1 → 0,1,2
multiB4C4 = 1/3 = 0 → batchBOffset_ 每轮 +0 → 0,0,0（x2 只有 1 个 batch）
```

- **含义**：不是"第几个 batch"，而是"当前 A/B 矩阵的数据索引"
- **维护**：`ProcessWithBatch` L286-343 通过 `multiA*C*` / `multiB*C*` broadcast 比率修正
- **复用**：scale 直接使用对应矩阵的 offset，自动继承 broadcast 语义

```cpp
{
```

**设计 — 新增两行（插在 bias 偏移 L303-304 之后、函数结束 `}` L305 之前）：**

```cpp
    // X1SCALE（pertokenScale）跟随 batchAOffset_，单 batch 元素数 = M × ceil(K/64) × 2
    Get<QuantBatchMatmul::IDX_X1SCALE_OFFSET>(blockOffset_) +=
        batchAOffset_ * params.problemShape.m *

    Get<QuantBatchMatmul::IDX_X2SCALE_OFFSET>(blockOffset_) +=
        batchBOffset_ * params.problemShape.n *
        Cmct::Gemm::CeilDiv(params.problemShape.k, static_cast<int64_t>(MXFP_DIVISOR_SIZE)) *
        MXFP_MULTI_BASE_SIZE;
```

**真实写法核对（基于源码确认）：**
- tuple 索引常量：`QuantBatchMatmul::IDX_X1SCALE_OFFSET`（=2）、`IDX_X2SCALE_OFFSET`（=3），定义在 `matmul/common/cmct/utils/quant_batch_matmul_constant.h` L38-39，与已用的 `IDX_A/B/C/BIAS_OFFSET`（0/1/5/4）同源。
- `blockOffset_` 是 `BlockOffset = AscendC::Shape<int64_t×6>`，X1SCALE/X2SCALE 槽位由 `coord.GetQuantOffset<MX_PERGROUP_MODE,...>()`（`utils/coord_utils.h` L350-394）在 `AddBatchOffset` 之前算好基址；本改动只在其上累加 batch 偏移。
- `CeilDiv` 用 `Cmct::Gemm::CeilDiv`（与本函数 L290 b 偏移分支同款调用）。常量 `MXFP_DIVISOR_SIZE`（=64）/`MXFP_MULTI_BASE_SIZE`（=2）在 `utils/common_utils.h` L53-54 定义，本文件经 L23 已 include，可直接用。

**与 Blaze #5 的对应关系：**

| | Blaze #5（2.6.5） | CMCT #5b（本节） |
|---|---|---|
| 偏移载体 | 原始 GM 指针 `pertokenScaleGmAddr_` / `scaleGmAddr_` | tuple `blockOffset_` 的 X1SCALE/X2SCALE 索引 |
| 写法 | `指针 += batchOffset × (...)` | `Get<IDX_X*SCALE_OFFSET>(blockOffset_) += batchOffset × (...)` |
| 索引语义 | 字节/元素由指针类型决定 | **元素索引**（`GlobalTensor<AType>` 下标），非字节 |
| pertokenScale 公式 | `batchAOffset_ × M × ceil(K/64) × 2` | 同 |
| scale 公式 | `batchBOffset_ × N × ceil(K/64) × 2` | 同 |

**关键差异 — 不带 sizeShift（高优先级坑）：**
- Blaze #5 的 a/b 指针偏移带 `>> sizeShift`（fp4 两元素打包进 1 字节，需右移）。**scale 偏移在两条路径都绝不带 sizeShift**：scale/pertokenScale 是 `fp8_e8m0_t`，每元素 1 字节、不打包，元素数即偏移。
- CMCT 写法天然不会误带：CMCT 的 a/b 偏移（L284/L298）本身就**没有** `>> sizeShift`（CMCT 的 fp4 字节差异在 b 的 NZ 分支用 `c0Size = C0_SIZE_B4 : C0_SIZE_B8` 处理，不是右移）。因此 X1/X2SCALE 两行直接照 M×ceil(K/64)×2 / N×ceil(K/64)×2 写即可，不存在"复制右移"风险。建议代码注释点明"scale 为 e8m0 每元素 1 字节、元素索引、无位移"。

**按 batch 偏移：** X1SCALE 跟随 `batchAOffset_`、X2SCALE 跟随 `batchBOffset_`，每轮 iteration 在 tuple 索引上累加当前 batch 偏移。

**fp8/fp4 共用：** fp8 与 fp4 共用同一段 `AddBatchOffset`，两行 scale 偏移对两种 dtype 都生效，无需按 dtype 分支。

# 4 FP4 transposeX2=false 支持设计（产品需求，golden 侧）

> 本章为纯设计。fp4 当前 golden（`golden_mx_matmul_batch.py` / `golden_mx_matmul.py`）只覆盖 transposeX2=true 一条路径（经 `x2_stored_transposed` 闸门），产品需求要求同时支持 transposeX2=false（约束 B 的 n>2 分支）。落地状态见 `施工进度.md`。

## 4.1 根因：fp4 的"×2 翻倍"发生在最内层存储维（打包语义）

`float4_e2m1fn_x2` 每字节打包 2 个 fp4，打包沿**张量的最内层（连续）维**发生：存储该维放逻辑元素数的一半，NPU 在算子内部按 dtype 标签把最内层 ×2 还原为逻辑维。算子侧两处实证（均以"存储最内层"为打包维，与转置属性无关）：

- op-plugin 输出 shape 推断 `QuantMatmulKernelNpuOpApi.cpp` L207-212：
  - `real_m = !trans_x1 ? x1_size_last_second : x1_size_last_second * FP4_IN_INT8`（`FP4_IN_INT8=2`）
  - `real_n = trans_x2 ? x2_size_last : x2_size_last * FP4_IN_INT8`
- meta 注册 `_meta_registrations.py` L3650-3651：`dim_n = n if x.last == w.last_second else n*2`。

解读 `real_n` 这一行（关键）：
- **trans_x2=true**：x2 存 `(..,N,K)`，最内层是 K。`x2_size_last = K_stored`，逻辑 N 取自 last（不 ×2）；翻倍发生在 K（最内层）→ `K_logical = K_stored*2`。
- **trans_x2=false**：x2 存 `(..,K,N)`，最内层是 N。`x2_size_last = N_stored`，逻辑 `N = N_stored*2`（×2 还原）；K 在 last_second，不翻倍。

x1 对称：trans_x1=false 时 x1 存 `(M,K)`、最内层 K 翻倍；trans_x1=true 时存 `(K,M)`、最内层 M 翻倍（real_m ×2）。

## 4.2 为何当前 int8-passthrough 模型只能走 transposeX2=true

当前 golden 用 int8 张量按"逻辑元素数满 K"灌满数据（`x1_shape=(M,K)`、fp4 与 fp8 同形），把 dtype 标签交给 NPU，自身不做 2:1 打包。于是脚本送进去的 x2 最内层维 = 逻辑值（未 /2），而 NPU 会对最内层再 ×2：

- **trans_x2=true 路径**：x1 存 `(M,K)` 最内层 K，x2 存 `(N,K)` 最内层也是 K。NPU 把两边最内层都 ×2 → x1 的 K 和 x2 的 K 同步翻倍、仍相等。脚本里 K=256 → NPU 视作 512，x1/x2 一致，能对齐。这正是 `x2_stored_transposed` 闸门让 fp4 借道 trans_x2 存储的原因。
- **trans_x2=false 路径**：x1 存 `(M,K)` 最内层 K（被 ×2 → 512），x2 存 `(K,N)` 最内层 N（被 ×2，K 在 last_second 不变 → 仍 256）。x1 的 K=512 ≠ x2 的 K=256 → 报 `K=512≠256`（即 施工进度.md 记录的 fp4 两例失败现象）。

根因一句话：**int8-passthrough 没做最内层 /2 打包，所以只有"K 恰好落在两侧最内层"的 trans_x2=true 能让两边同步翻倍而保持相等；trans_x2=false 时 K 不在 x2 最内层，x2 的 K 不翻倍，与 x1 翻倍后的 K 不匹配。** 文档允许 transposeX2=false，是因为产品/算子约定调用方按真实 fp4 打包送数据（x2 存 `(K, N/2)`，最内层 N 已 /2），NPU ×2 还原 N、K 保持逻辑值即对齐。当前 golden 不可达此路径，正是因为缺这一步 /2 打包。

## 4.3 当前模型能否支持：不能，缺真正的 2:1 打包

结论：int8-passthrough 模型**无法**验证 fp4 transposeX2=false。缺的不是数值模型（matmul 部分仍可复用 fp8 golden），而是**数据构造侧的最内层 2:1 打包**——必须让送 NPU 的 x2 存 `(K, ceil(N/2))`、x1 存 `(M, ceil(K/2))`，使 NPU ×2 还原后的逻辑 shape 与 golden 的逻辑 shape 一致。

## 4.4 推荐设计方案

### 4.4.1 真正的 fp4 打包（最小实现）

新增打包辅助：把"逻辑 fp4 值张量"沿最内层每 2 个元素打包进 1 个 int8（uint8 容器），低/高 nibble 顺序需上板对齐（见风险）。golden 数值侧仍用解包后的逻辑值跑 fp8-style 计算，仅 NPU 入参用打包后的张量。

最小思路（伪码）：
- 生成逻辑值张量 `x_logical`（小整数，落在 e2m1 可表示点），形状取逻辑 shape。
- `pack_fp4_lastdim(x_logical)`：对最内层 reshape `(..., L/2, 2)`，两元素编码进 1 字节（`lo | (hi<<4)`，编码用 e2m1 4-bit 码，或——若仅验证 shape 对齐与 batch 偏移而非真值——沿用小整数直填、靠 NPU cube 的 e2m1 decode，与现有 int-passthrough 同理但维度 /2）。
- golden 侧用 `x_logical` 直接算（无需解包，逻辑值已在手）。

注：依 memory [[qbmm-mx-fp4-golden]]，repo 全链路无真实 e2m1 LUT，cube 内部 decode 对小整数精确。所以打包**只需保证 shape 的 /2 与最内层定位正确**即可让 K 对齐；nibble 内的真值编码若用小整数 passthrough 仍可过（与现有 fp4 用例同假设），无需引入完整 e2m1 编码表——除非要验证非整数 e2m1 真值（那必须上板对数 + 确认 nibble 序）。

### 4.4.2 golden 侧 x2/x2Scale 布局（满足约束 A：转置属性一致，此处都"非转置"）

transposeX2=false 时：
- x2 存储 `(..,K, ceil(N/2))`（最内层 N 打包 /2），逻辑 `(..,K,N)`。
- x2Scale 与 x2 转置属性一致 → 非转置布局 `(..,ceilK, N, 2)`（scale 为 e8m0，永不打包，N 维不 /2）。
- x1 维持非转置 `(M, ceil(K/2))` 打包、x1Scale `(M, ceilK, 2)`。

即 `x2_stored_transposed` 闸门对该用例应返回 **false**，golden 走"非转置 sc reshape"分支（已存在），数据生成切到打包路径。

### 4.4.3 n>2 边界用例

约束 B（transposeX2=false 分支，见 proto.h L130）：n 必须 > 2。
- 正向：n=3 应 PASS（需 N 为偶以满足 fp4 内轴偶数？注意：transposeX2=false 时 x2 最内层是 N，受"内轴偶数"约束 → N 必须偶。n=3 与"内轴偶数"冲突）。**待澄清点**：n>2 与内轴偶数同时成立的最小正向 N 应为 **4**（偶且>2）；n=3 可能被内轴偶数拒。建议正向用 N=4，另设 N=3 观察是否被内轴偶数拦。
- 负向：n=2 应被拒（违反 n>2）；N=1 同理。

### 4.4.4 风险点与算子侧依赖

- **nibble 打包序未知**：低/高 nibble 与逻辑元素的对应、以及 e2m1 4-bit 编码表，repo 无源可考（memory [[qbmm-mx-fp4-golden]] 明确"cannot confirm pack order / value LUT"）。小整数 passthrough 可绕开，但若要真值对数必须上板实测确定。
- **内轴偶数 vs n>2 的交互**：transposeX2=false 时 N 是内轴，既要偶又要>2，最小正向 N=4，需上板确认 n=3 的实际拒/过。
- **算子侧无需改动**：transposeX2=false 是算子已支持路径（proto.h 明列、host checker 无额外拦截），本设计纯 golden 侧；不依赖 #1–#5 之外的算子改动。但 batch + transposeX2=false 组合的 scale 偏移仍依赖 #5/#5b 已上板。
- **依赖 #6（op-plugin transpose check，commit 6c2885f9）上板**：与 fp8 转置用例同一依赖。

### 4.4.5 工作量与分步建议

1. 加 `pack_fp4_lastdim` 辅助（约 15 行）+ 在 `gen_data` 对 fp4 走打包分支（按 trans_x2 决定打包哪一维）。
2. 调整 `x2_stored_transposed`：fp4 不再无条件返回 true，改为"按 c.trans_x2 实际值"——即放开 fp4 也能走非转置，由打包保证 K 对齐。需同步 golden 的 sc/ps reshape 分支（已支持两路）。
3. 先做小整数 passthrough 版（仅验 shape/K 对齐 + checker 拒绝逻辑），上板过基本用例。
