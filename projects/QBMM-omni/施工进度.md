## 5. 待办编排（用户已确认 + 任务 B 新发现）

### [待办-3] a8w4 / fbias 是否可绕 aclnn 约束

- **a8w4**：`EH0012 yOffset 当前版本不支持` — 需查当前 CANN 版本是否真的全 A2A3 路径都不支持 yOffset，还是仅特定 dtype 组合。若确认不支持，需评估：(a) 是否绕 aclnn 直接走底层 l0op；(b) 是否升 CANN 版本；(c) 是否 scope-out。
- **fbias**：`EZ0020 bias=INT32` 在 trans_quant_param 转 int64 scale 后强制 — 需查是否所有 fp32 scale + fp32 bias 路径都被拒，还是仅特定 mode。
- **协作**：host-engineer（aclnn checker 实际行为 / l0op 直调可行性）+ kernel-semantics-researcher（yOffset/float-bias 在 A2A3 kernel 的真实数学语义，是否在 kernel 内被截断/忽略）。
- **本轮**：仅编排，不执行。

### [待办-4] perblock 形状泛化 + verifier 证据等级复核

- 现状：单例（M=128,N=512,K=512,gK=gN=128,ND,bf16 out），未泛化。
- 需补：不同 M（小/大）、不同 groupSize（gN/gK 在 V5 doc 允许的 [1,128,128] 内）、NZ 路径、带 bias（V5 doc:651 G-B 支持 bias=FLOAT32）。
- **协作**：verifier 须复核"单例通过 ≠ perblock 通"，证据等级从弱升强需多形状点。
- **本轮**：仅编排。

### [待办-5] aclnn eager 通路验证

- 现状：golden 全走 PyTorch binding，aclnn eager 直调零覆盖。
- 需补：构造最小 aclnn eager 用例（参考 ops-nn examples/test_aclnn_quant_matmul_v5_*.cpp），分别调 V5(ND) / WeightNz(NZ) 入口。
- **协作**：host-engineer。
- **本轮**：仅编排。

### [任务 B 新发现] int4×4 K-G pergroup 非对称 — 未迁移分支

- **aclnn 文档佐证**：`ops-nn/matmul/quant_batch_matmul_v4/docs/aclnnQuantMatmulV5.md:715-743` 明确列出 A2A3 支持 K-G 模式（INT4×INT4 + FLOAT scales + FLOAT16 offset + out=BFLOAT16/FLOAT16）。
- **omni-ops 现状**：v4 op_kernel 已含 `ai_infra_quant_batch_matmul_v4_pergroup.h`（强证据：源码可核），即 kernel 层已迁；但 **golden 零覆盖**（无对应 case）。
- **优先级**：高 — kernel 已迁但无验证 = 沉默风险。需补 golden case（K-G 需要 k%1024==0 + n%256==0 + xOffset/FLOAT16 offset 构造）。
- **协作**：kernel-semantics-researcher（K-G 数学语义 + golden 期望函数 `_compute_t_cg` 骨架适配）。

### [任务 B 新发现] V4 核 NZ 路径 — 未迁移分支

- **aclnn 文档佐证**：`aclnnQuantMatmulWeightNz.md` 整篇即 NZ 入口；其内部分派 a8w4-int/a8w4-float 到 V4 核（修改清单 §3.1）。
- **omni-ops 现状**：aclnn_ai_infra_quant_matmul_v4.cpp（含 WeightNz）已迁（强证据），但 golden 仅覆盖 V3 核 NZ（pertoken/perchannel/int32 等的 NZ 变体），**V4 核 NZ 路径（a8w4 NZ）零覆盖**。
- **优先级**：与 a8w4 disabled 强绑定 — 一旦 a8w4 约束解掉（待办-3），此路径才有意义；当前标 **被待办-3 阻塞**。

## 6. 待办优先级建议

按"风险 vs 收益 + 阻塞关系"排序：

1. **[高] 待办-4 perblock 泛化**：kernel 已迁、单例已通，但泛化证据弱，是当前最高"已迁完但未充分验证"项。投入小、收益直接。
2. **[高] K-G pergroup golden 补全**（任务 B 新发现）：kernel 已迁、文档明确支持，零验证 = 沉默风险。投入中（需 golden 函数适配）。
3. **[中] 待办-3 a8w4/fbias 约束排查**：a8w4 阻塞 V4 核 NZ 路径；fbias 影响 fp32 bias 路径完整性。投入大（需 host + semantics 协作），可拆两步并行。
4. **[中] 待办-5 aclnn eager 通路**：补全通路矩阵，但 binding 已通，eager 直调增量价值取决于后续是否要单独发 aclnn .so。投入小。
5. **[低/后置] 图模式**：用户明确后置，本轮不排。

**推进顺序遵守 CLAUDE.md §2.5**：ops-nn 先改先编。但本轮纯文档，无改码；后续若涉及代码，仍按"ops-nn → omni-ops"序（omni-ops 是消费方，ops-nn 是上游真值）。
