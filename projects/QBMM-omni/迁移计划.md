# QBMM 算子迁移至 omni-ops — 迁移计划

> **状态**: 设计 / 待审批（未改任何源码）。已逐层源码审查（torch → aclnn → kernel → tiling → 依赖 → config）+ 逐项决策闭合。
> **芯片**: A2A3（910B `ascend910b` / 910C `ascend910_93`，均 `DAV_2201`）ONLY。DEFER：**arch35=A5(950)**、**arch20=310P(DAV_2002)**、Kirin。
> **源仓**: `ops-nn`（算子 v3/v4）+ `op-plugin`（torch binding）
> **目标仓**: `omni-ops`
> **总原则**: **有选择就照 `ai_infra_matmul` 的实际做法**（已迁移、已发货的先例）。

## 2. 范围

### 2.1 量化模式（以 aclnn `aclnnQuantMatmulV5.md` A2/A3 约束段为准，torch 表2 是子集）

| 模式 | 状态 |
|------|------|
| W8A8 pertensor/perchannel（int8×int8, scale uint64/int64, out fp16/int8）| IN |
| W8A8 pertoken（scale fp32/bf16 + pertoken fp32, out bf16/fp16）| IN |
| int8 G-B perblock（scale fp32, group[1,128,128], out bf16）| IN（v3 `_block.h` int8 路径，裁剪勿误删）|
| INT4×INT4（int4 或 int32-packed；含 K-G pergroup）| IN |
| A8W4（int8×int32, x1Scale fp32, x2Scale uint64/int64, yOffset fp32）| IN（走 V4，A2A3 有核）|
| W8A8 → int32 out | IN |
| fp8/hifloat8 perblock、MX、B-B、T-CG | DEFER（950-only）|

transB：x1/x2 转置全组合、ND、NZ(WeightNz) 全 IN。

### 2.2 明确排除

- A5/950：arch35 kernel+tiling、Blaze、CMCT、MX/e8m0/fp4、fp8-perblock
- **310P：arch20 kernel+tiling（PpMatmulInt8Tiling=`ASCEND310P`、PertokenArch20=`DAV_2002`）**
- Kirin
- op-plugin 融合变体（gelu/reduce_sum/dequant/add_）

## 3. 完整链路（分派全景）

### 3.1 dispatch

```
torch: npu_ai_infra_quant_matmul (custom)
  → aclnnAiInfraQuantMatmulV5 (ND) / aclnnAiInfraQuantMatmulWeightNz (NZ)   [v5.cpp:1157-1168]
     ├ normal (int8×int8 全模式 / int4×int4 对称 / int32-out / bf16 / pertoken)
     │   → l0op::QuantBatchMatmulV3 → v3 kernel（顶层 v3.cpp，__CCE_AICORE__==220，A2A3）
     └ 特殊 (isA8W4 / isA8W8Perblock / isA4W4PergroupNonSymmetric)
         → l0op::QuantBatchMatmulV4 → v4 顶层 v4.cpp（__CCE_AICORE__==220，A8W4/MSD/perblock/pergroup）
                                       [arch35/ = 950，DEFER]
```

### 3.2 host tiling（模板注册 + IsCapable 优先级）

- `IMPL_OP_OPTILING` 入口按 arch 分流（`tiling.cpp:1560-1575`）：910b(DAV_2201) → `TilingRegistry{0,1,2}`。
- **A2A3 实际用的模板**：`QuantBatchMatmulV3BasicTiling`(prio0，恒真优先) / `QuantBatchMatmulV3Tiling`(prio2，兜底)。
- `PpMatmulInt8Tiling`(prio1) = **310P only**（IsCapable=`ASCEND310P`）→ 剥离（决策10）。
- arch35 的 `_WITH_ARCH` 模板（AdaptiveSlidingWindow*×5/StreamK/Iterbatch）= A5 → DEFER。
- **group 推断 3 层各留勿重写**：op-plugin `check_and_get_groups`(打包) → aclnn `InferGroupSize`(checker.cpp:697) → host `AnalyzeGroupInfo`(tiling_base.cpp:714)。

### 3.3 A8W4 在 A2A3 有 kernel — 本地已证

`func.cmake:617-675`：空 `add_kernel_sources` = 编默认顶层 `<op>.cpp`（`:621/671`）给所有 SoC（`:622/645`），由 `config/<soc>/<op>_binary.json` 存在 gate（`:656`）。**`config/ascend910b/` + `910_93/` 的 v4_binary.json 都存在** + 顶层 `v4.cpp:66-73` 有 `__CCE_AICORE__==220` A8W4 码 ⇒ A8W4/perblock/pergroup 在 A2A3 有核。上板仅验数值。

> **A2A3 覆盖本地判定通法**：①`config/ascend910b/<op>_binary.json` 存在 + ②kernel `__CCE_AICORE__==220` 覆盖该模式 + ③`add_kernel_sources` COMPUTE_UNITS(空=ALL)。

### 3.4 确定性 & batch

- **确定性**：A2A3 **默认确定**。唯一非确定源 StreamK（A5，动态 K 切分+原子累加），由 `GetDeterministic()` gate（streamk_tiling.cpp:904）。默认 split-K 靠核↔块静态映射保序。无对外 attr。
- **batch 广播**：numpy 式右对齐（一方为1可广播，两方>1不等报错），infershape + op-plugin 两处校验。**无 batch_invariant 特性**。

## 4. torch binding 契约（op-plugin → torch_ops_extension）

**契约（9 参，照 A2A3 文档）**：
```
npu_ai_infra_quant_matmul(Tensor x1, Tensor x2, Tensor scale, *,
    Tensor? offset=None, Tensor? pertoken_scale=None, Tensor? bias=None,
    int? output_dtype=None, int[]? group_sizes=None) -> Tensor
```
（op-plugin 原 13 参丢弃 `x1_dtype/x2_dtype/pertoken_scale_dtype/scale_dtype/y_scale`——MX/A5 专用）

**变换（非复制，按 custom 范式重写，源 `QuantMatmulKernelNpuOpApi.cpp`）**：

| 维度 | op-plugin | omni-ops |
|------|-----------|---------|
| namespace | `op_api` | `custom`（`torch.ops.custom.*`）|
| schema/meta | yaml 生成 | 手写 `m.def` + `_meta` |
| EXEC 宏 | `EXEC_NPU_CMD` | `EXEC_NPU_CMD_V1` |
| aclnn | V5/WeightNz | `aclnnAiInfraQuantMatmulV5`/`...WeightNz` |
| 注册 | yaml | `TORCH_LIBRARY_IMPL(custom, PrivateUse1+Meta)` |

**内部依赖**：`npu_trans_quant_param`（scale fp32→int64；op-plugin L286-296 + aclnn V5:627）。**A8W4 路由**：`offset→yOffset`（L245-249）。**保留 checker**：`is_x_scale_same_transpose` [[qbmm-data-scale-transpose-must-match]]、`check_and_get_groups`。
**新建**：`torch_ops_extension/.../quant_batch_matmul_v3/csrc/npu_ai_infra_quant_matmul.cpp` + `__init__.py` + `ops_def_registration.cpp` 追加 `m.def`。

## 5. omni-ops 打包 + CMakeLists（照 ai_infra_matmul 实测）

- **自动发现**：放好 CMakeLists 即可（`func.cmake op_add_subdirectory` glob）。`build.sh -n <op> -c <soc>` 过滤。
- **host target**：`optiling` / `opsproto` / `opapi`（+ `opmaster_ct`，`NOT BUILD_OPEN_PROJECT` 时）；手写 aclnn 入口归 `op_host_aclnnInner`；kernel 由 bisheng 编 `.run`。
- **CMake 模型**：omni-ops **无** `add_modules_sources` → 必须 `target_sources` + `add_ops_compile_options(OP_NAME ...)`，CMakeLists 完全重写。
- **common 代码编进本算子 target**（相对路径 `../common/...`，非单独链接）。

## 7. 命名落地（全改，照 matmul）

matmul 实测：`OP_ADD(AiInfraMatmul)` / `IMPL_OP_INFERSHAPE(AiInfraMatmul).InferShape(InferShapeForAiInfraMatmul)` / `REGISTER_TILING_TEMPLATE("AiInfraMatmul", AiInfraMatmulBaseTiling, 0)` / `IMPL_OP_OPTILING(AiInfraMatmul)`——字符串 key + infer 函数名 + tiling 类名全改。

QBMM 逐点（V3/V4 同理，`QuantBatchMatmulV3` → `AiInfraQuantBatchMatmulV3`）：
- `op_graph`：`REG_OP`
- `def.cpp`：OpDef 类 + `OP_ADD`
- `infershape.cpp:56`：`IMPL_OP_INFERSHAPE` + infer 函数名
- `tiling.cpp:1610`：`IMPL_OP_OPTILING`
- `tiling.cpp:1557/1558` + `basic_tiling:1430`：`REGISTER_TILING_TEMPLATE` 字符串 + **tiling 类名**（`QuantBatchMatmulV3BasicTiling` 等）
- `l0op::QuantBatchMatmulV3` 建的节点 type
- aclnn `aclnnQuantMatmul*` → `aclnnAiInfra*`
- config：binary.json + runtime_kb.json 文件名 + **KB 内 `"op"` 字段(sed)**

**纪律**：改完 grep 全仓无残留旧名。**风险**：字符串 key 漏一处 → runtime dispatch 静默断。
