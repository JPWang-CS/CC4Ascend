> **⚠ 2026-07-17 行号勘误（据当前 ops-nn HEAD 实测）**：本文行号比当前 HEAD 系统性偏前 ~3 行——REGISTER prio1 标 :1557 实测 :1560、prio2 :1558→:1561、IMPL :1610→:1613、PertokenArch20 :1570-1571→:1573-1574、registerList :1573→:1576、arch35 分支 :1566-1569→:1568-1572。**实施时一切行号以 grep 实测为准，勿照搬本文。** 又：supportMmadS8S4 字段决定**保留**(Option A, 见 §1 #17)；op_host **扁平化**(H3=B, 见 §1 #18)——本算子 tiling 直接放 `op_host/`(无 `op_tiling/`)，`op_host/op_tiling/foo` 目标引用→`op_host/foo`，common 与 ops-nn 源不变。
> **芯片**: A2A3（910B `ascend910b` / 910C `ascend910_93`，均 `DAV_2201`）ONLY。剥离：**arch35=A5(950)**、**arch20=310P(DAV_2002)**、Kirin。
> **arch35 定性（已核实）**: arch35/DAV_RESV(s8s4) 对 A2A3 是**死代码**，A2A3 永不进入（`GetCurNpuArch()` 对 910B/910_93 返回 `DAV_2201`，`IsAdvancedArch` 只放行 `{DAV_3510, DAV_RESV}`）。故 arch35 **整删**，非"保留待用"。s8s4≠A8W4：A8W4(int8×int4) 在 A2A3 走 MSD+int32 打包（`v4.cpp:67-97`，220 保护内），不依赖 arch35。详见 §6.1/§6.2。
> **源仓**: `ops-nn`（算子 v3/v4）+ `op-plugin`（torch binding）
> **目标仓**: `omni-ops`
> **总原则**: **有选择就照 `ai_infra_matmul` 的实际做法**（已迁移、已发货的先例）。

## 2. 范围

### 2.1 量化模式（以 aclnn `aclnnQuantMatmulV5.md` A2/A3 约束段为准，torch 表2 是子集）

| 模式 | 状态 |
|------|------|
| W8A8 pertensor/perchannel（int8×int8, scale uint64/int64, out fp16/int8）| IN |
| W8A8 pertoken（scale fp32/bf16 + pertoken fp32, out bf16/fp16）| IN |
| int8 G-B perblock（scale fp32, group[1,128,128], out bf16）| IN（v3 `_block.h` int8 路径，裁剪勿误删）|
| INT4×INT4（int4 或 int32-packed；含 K-G pergroup）| IN |
| A8W4（int8×int32, x1Scale fp32, x2Scale uint64/int64, yOffset fp32）| IN（走 V4，A2A3 有核）|
| W8A8 → int32 out | IN |
| fp8/hifloat8 perblock、MX、B-B、T-CG | 剔除（950-only）|

transB：x1/x2 转置全组合、ND、NZ(WeightNz) 全 IN。

### 2.2 明确排除

- A5/950：arch35 kernel+tiling、Blaze、CMCT、MX/e8m0/fp4、fp8-perblock
- **310P：arch20 kernel+tiling（PpMatmulInt8Tiling=`ASCEND310P`、PertokenArch20=`DAV_2002`）**
- Kirin
- op-plugin 融合变体（gelu/reduce_sum/dequant/add_）

## 3. 完整链路（分派全景）

### 3.1 dispatch

```
torch: npu_ai_infra_quant_matmul (custom)
  → aclnnAiInfraQuantMatmulV5 (ND, 分派 if @v5.cpp:1158) / aclnnAiInfraQuantMatmulWeightNz (NZ, 分派 if @v3/op_api/aclnn_quant_matmul_v4.cpp:1838)
     ├ normal (int8×int8 全模式 / int4×int4 对称 / int32-out / bf16 / pertoken)
     │   → l0op::QuantBatchMatmulV3 → v3 kernel（顶层 v3.cpp，__CCE_AICORE__==220，A2A3）
     └ 特殊 (isA8W4 / isA8W8Perblock / isA4W4PergroupNonSymmetric)
         → l0op::QuantBatchMatmulV4 → v4 顶层 v4.cpp（__CCE_AICORE__==220，A8W4/MSD/perblock/pergroup）
                                       [arch35/ = 950，整删]
```

### 3.2 host tiling（模板注册 + IsCapable 优先级）

- `IMPL_OP_OPTILING` 入口按 arch 分流（`tiling.cpp:1563-1579`）三叉：`if(IsAdvancedArch)`=arch35 / `else if(IsSocVersionArch20Pertoken)`=arch20 / `else`=A2A3 `TilingRegistry{0,1,2}`。剥离 arch35+arch20 后 A2A3 单路。
- **三模板注册 key 全是算子名 `"QuantBatchMatmulV3"`**（非各自类名）：`basic_tiling.cpp:1430` BasicTiling(prio0) / `tiling.cpp:1560` PpMatmulInt8Tiling(prio1) / `tiling.cpp:1561` V3Tiling(prio2)。改名时 3 处 key 统一改 `AiInfraQuantBatchMatmulV3`，类名各自加前缀。
- **A2A3 实际用**：`BasicTiling`(prio0，仅 910B，`basic_tiling.cpp:275` IsCapable 只放行 ASCEND910B) / `V3Tiling`(prio2，catch-all 恒真)。
- `PpMatmulInt8Tiling`(prio1) = **310P only**（IsCapable=`ASCEND310P`，`pp_matmul_int8_tiling.cpp:80`）→ 剥离。**删 prio1 注册必须同步 `registerList{0,1,2}→{0,2}`**：普通 `TilingRegistry::DoTilingImpl`(`tiling_templates_registry.h:447`) 用 `operator[]` 非 `find`，缺 prio 会调空函数指针**崩溃**（非跳过）。
- arch35 的 `_WITH_ARCH` 模板（AdaptiveSlidingWindow*/StreamK/Iterbatch）+ 第一分支 = A5/DAV_RESV → **整删**（对 A2A3 死代码）。
- **group 推断 3 层各留勿重写**：op-plugin `check_and_get_groups`(打包) → aclnn `InferGroupSize`(checker.cpp:697) → host `AnalyzeGroupInfo`(tiling_base.cpp:714)。

### 3.3 A8W4 在 A2A3 有 kernel — 本地已证

`func.cmake:617-675`：空 `add_kernel_sources` = 编默认顶层 `<op>.cpp`（`:621/671`）给所有 SoC（`:622/645`），由 `config/<soc>/<op>_binary.json` 存在 gate（`:656`）。**`config/ascend910b/` + `910_93/` 的 v4_binary.json 都存在** + 顶层 `v4.cpp:66-73` 有 `__CCE_AICORE__==220` A8W4 码 ⇒ A8W4/perblock/pergroup 在 A2A3 有核。上板仅验数值。

> **A2A3 覆盖本地判定通法**：①`config/ascend910b/<op>_binary.json` 存在 + ②kernel `__CCE_AICORE__==220` 覆盖该模式 + ③`add_kernel_sources` COMPUTE_UNITS(空=ALL)。

### 3.4 确定性 & batch

- **确定性**：A2A3 **默认确定**。唯一非确定源 StreamK（A5，动态 K 切分+原子累加），由 `GetDeterministic()` gate（streamk_tiling.cpp:904）。默认 split-K 靠核↔块静态映射保序。无对外 attr。
- **batch 广播**：numpy 式右对齐（一方为1可广播，两方>1不等报错），infershape + op-plugin 两处校验。**无 batch_invariant 特性**。

## 5. omni-ops 打包 + CMakeLists（照 ai_infra_matmul 实测）

- **自动发现**：放好 CMakeLists 即可（`func.cmake op_add_subdirectory` glob）。`build.sh -n <op> -c <soc>` 过滤。
- **kernel 无 add_kernel_sources**：omni-ops **无** `add_kernel_sources` API，ai_infra_matmul **无** `op_kernel/CMakeLists.txt`。kernel 源靠 `func.cmake add_ops_src_copy` 的 `file(GLOB op_kernel/*)` 全量收（排除 ophost）；soc 编译范围靠 `config/<soc>/` 目录存在 + `build.sh -c`，非 CMake soc 列表。→ 不迁 `op_kernel/CMakeLists.txt`；`arch20/`、`arch35/` 子目录**物理删**（glob 递归收，不删会编译失败）。
- **host target**：`optiling` / `opsproto` / `opapi`（+ `opmaster_ct`，`NOT BUILD_OPEN_PROJECT` 时）；手写 aclnn 入口归 `op_host_aclnnInner`；kernel 由 bisheng 编 `.run`。
- **CMake 模型**：omni-ops **无** `add_modules_sources` → 必须 `target_sources` + `add_ops_compile_options(OP_NAME ...)`，CMakeLists 完全重写。
- **common 代码编进本算子 target**（相对路径 `../common/...`，非单独链接）。

## 9. 实施 Phase（torch 前置重排）

> 改码前先讨论、小步迭代 [[ascendc-workflow-prefs]]。编译/运行验证需 Ascend 开发机。
> **重排原则**：torch binding **不排最后**——aclnn 一编完就接，让每个迁移阶段有端到端数值验证（对 golden），避免"编译过/UT 假过"到最后接 torch 才发现数值错、难回溯。最小可调用闭环 = v3 核 + V5 入口层，先验 V3 路径；v4 核层后迁再验 V4 路径。

- **P0 环境**：clone + `source setenv.bash` + 确认 bisheng
- **P1 common**：补 `log_format_util.h`（→`common/op_host/`）+ `quant_matmul_v4.{h,cpp}`（→`common/op_host/op_api/`）进 omni-ops common
- **P2 v3 全套 + v4 入口层**：复制 v3 A2A3 文件 + 删 arch20 挂钩(含 registerList→{0,2}) + 删 arch35 挂钩 + 删 A5/310P config + 改 AiInfra 名 + 重写 v3 CMakeLists + KB 改名 sed；**同时迁 v4 入口层**（`aclnn_quant_matmul_v5.{h,cpp}` + `quant_matmul_common_check.{h,cpp}` + 最小 v4 def/CMakeLists 使 V5 可 install）→ `build.sh -c ascend910b` 编出 .run + install aclnn。**ND→V3 核路径通**。
  - ⚠ **P2 探针**：确认 V5 aclnn 能否独立于 v4 核层(def/tiling/kernel)先编+install（编译上只依赖 common l0op executor 声明，理论可行；omni-ops opapi 打包是否要求 V5 挂完整 v4 算子需实测）。若不允许拆，退档：v3+v4 host 全迁完再接 torch。
- **P3 torch 早接**：`m.def` 追加 `csrc_base/ops_def_registration.cpp` + per-op `npu_ai_infra_quant_matmul.cpp`（impl+`_meta`+`TORCH_LIBRARY_IMPL`×2）+ `__init__.py` → 装 wheel。torch 可调 `torch.ops.custom.npu_ai_infra_quant_matmul`。
- **P4 验 V3 路径**（首个端到端闭环）：构造 golden 脚本（§10），跑 **V3 核**用例——W8A8 pertensor(T-C)/perchannel(T-T)/pertoken(K-C)、int8→int8(requant)、int8→int32、int4×int4 对称——对 golden。

- **P7 收尾**：迁 UT（`test_aclnn_*` 防 0-test 假过）+ ctest；全仓 grep 无残留旧名 + run 验 dispatch；KB 命中验证。

## 10. 验证与 golden

**范式**（照 omni-ops `ai_infra_matmul/tests/st/test_ai_infra_matmul.py`）：`torch.ops.custom.npu_ai_infra_quant_matmul(...)` 调实际 → numpy 算 golden → `verify_result`（isclose + error_ratio 阈值）。pytest 按 **P4 组(V3 核)/P6 组(V4 核)** 两 class 组织，与验证顺序对齐。

**golden 源**：ops-nn `quant_batch_matmul_v3/v4/tests/assets/golden.py`（与算子同源的 numpy 参考，含各 dtype 容差表）。重构方式：抽量化计算函数（剥掉 TTK 框架的 `customize_inputs`/`Assets`/`__golden__`），配输入构造（按各模式 dtype/scale 约束）+ torch 调用 + 对比；容差用 golden.py 的 `tolerance` 表。op-plugin `test/test_custom_ops/test_npu_quant_matmul.py` 参考输入构造。

**case → 验证节点映射**：

| 节点 | 量化模式（A2A3）| 落核 | golden 现成函数 | 现成度 |
|---|---|---|---|---|
| **P4** | W8A8 pertensor(T-C)/perchannel(T-T) | V3 | v3 `_compute_tc` | ✅ 完整 |
| | W8A8 pertoken(K-C/K-T) | V3 | v3 `_compute_pertoken` | ✅ |
| | int8→int8(requant) / int8→int32 | V3 | v3 `_compute_requant`/`_compute_int32` | ✅ |
| | int4×int4 对称 | V3 | v3 int32-matmul + T-C | ✅ |
| **P6** | A8W4-int(int8×int32) MSD | V4 | v4 `_compute_k_c` | ⚠️ 需适配(int32 解包) |
| | W8A8 perblock(int8, G-B) | V4 | v3 `_compute_perblock` | ⚠️ 现成 fp8/hif8，int8 要改 |
| | int4×int4 pergroup 非对称(K-G) | V4 | v4 `_compute_t_cg` | ⚠️ 现成 fp8×fp4，int4 要改 |

**剔除**（950-only，不测）：MX(G-G `_compute_mx`)、fp8-perblock(B-B)、fp8×fp4(`_compute_t_cg` 原用途)。
**注**：V3 组 golden 现成完整（P4 拿来即用）；V4 组三模式需基于 aclnn `V5.md` 公式 + `_compute_k_c` 骨架适配——恰与"V4 核层最后迁"对齐，不阻塞 P4。
