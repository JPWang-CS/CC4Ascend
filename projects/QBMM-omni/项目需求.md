## 1. 项目概述

### 1.1 项目目标

将 QBMM (QuantBatchMatmul V3/V4) 算子从 ops-nn 仓库迁移至 omni-ops 仓库，目标是保持与原算子完全一致的功能和性能，同时遵循 omni-ops 的项目结构和命名规范。

### 1.2 迁移范围

#### 1.2.1 芯片范围（A2A3 only）

**明确支持**: A2A3 芯片（第二代、第三代 AI 处理器）
- Ascend 910B (`ascend910b`, `DAV_2201`)
- Ascend 910C (`ascend910_93`, `DAV_2201`)

**编译条件**: `__CCE_AICORE__ == 220`

**明确排除**:
- A5 (Ascend 950, `DAV_3510`, arch35)
- 310P (`DAV_2002`, arch20)
- Kirin 系列芯片

#### 1.2.2 知识库（KB）迁移要求

**迁移范围**: 保留并迁移所有 A2A3 相关的 runtime_kb 机制

**具体要求**:
1. KB 文件迁移:
   - `*_runtime_kb.json` 文件从 ops-nn 迁移到 omni-ops
   - 文件名改为 `AiInfraQuantBatchMatmulV3_runtime_kb.json`

2. KB 内容修改:
   - JSON 内 `"op"` 字段从 `"QuantBatchMatmulV3"` 改为 `"AiInfraQuantBatchMatmulV3"`
   - 保持所有 tiling 逻辑和参数不变

3. KB API 引用:
   - 引用 common 目录的 `runtime_kb_api.cpp`
   - 确保 KB 注册机制正确

**KB 功能验证**:
- 运行已知 shape 用例，检查是否命中 KB tiling
- 确保 KB 性能优化与原算子一致

#### 1.2.3 适配 omni 仓要求

**项目结构适配**:
1. 目录结构完全按照 `ai_infra_matmul` 模式:
   ```
   omni-ops/inference/ascendc/src/ops-nn/matmul/
   ├── ai_infra_quant_batch_matmul_v3/
   │   ├── CMakeLists.txt
   │   ├── op_host/
   │   ├── op_api/
   │   ├── op_kernel/
   │   ├── docs/
   │   └── tests/
   └── ai_infra_quant_batch_matmul_v4/
       └── (同上结构)
   ```

2. CMakeLists 适配:
   - 使用 `add_ops_compile_options` 而非 `add_modules_sources`
   - op_host_aclnnInner 只包含本目录的 def.cpp
   - optiling/opapi/opsproto target_sources 显式声明
   - 移除跨目录引用（v3 不引用 v4 的 aclnn）

3. aclnn 接口位置:
   - V5 接口放在 `v4/op_api/` 根目录（不是 op_host/op_api）
   - V3/V4/WeightNz 接口放在 `v3/op_api/` 根目录

4. 编译产物:
   - vendor_name: `omni_custom_transformer`
   - 与 `ai_infra_matmul` 共享同一个 .run 包

### 1.3 参考模板

本迁移严格参照 `ai_infra_matmul` 算子的已迁移模式，该算子已完成从 ops-nn 到 omni-ops 的迁移并成功发货。

## 2. 功能需求

### 2.1 支持的量化模式

| 量化模式 | x1 | x2 | x1Scale | x2Scale | offset | bias | output | 状态 |
|----------|----|----|---------|---------|--------|------|--------|------|
| W8A8 pertensor (T-C) | INT8 | INT8 | null | UINT64/INT64 | null | null/INT32 | FP16/INT8 | IN |
| W8A8 perchannel (T-T) | INT8 | INT8 | null | UINT64/FLOAT/BF16 | null | null/INT32 | FP16/INT8 | IN |
| W8A8 pertoken (K-C/K-T) | INT8 | INT8 | FLOAT[M] | FLOAT/BF16[N] | null | null | BF16/FP16 | IN |
| INT4×INT4 对称 | INT4 | INT4 | null | UINT64 | null | null | - | IN |
| W8A8 perblock | INT8 | INT8 | FLOAT(≥2D) | FLOAT(≥2D) | null | FLOAT32 | BF16 | IN |
| INT4×INT4 pergroup 非对称 | INT4 | INT4 | FLOAT[M,1] | FLOAT[⌈k/g⌉,N] | FLOAT16 | null | - | IN |
| A8W4-int | INT8 | INT32 | FLOAT | FLOAT/UINT64 | FLOAT(yOffset) | null | - | IN |
| W8A8 → int32 out | INT8 | INT8 | - | - | - | - | INT32 | IN |

### 2.2 支持的数据类型

| 输入类型 | 说明 |
|----------|------|
| INT8 | 8位整数 |
| INT4 | 4位整数（INT32-packed） |
| INT32 | 用于 A8W4 的 x2 |
| FLOAT16 | 半精度浮点 |
| BFLOAT16 | bfloat16 格式 |
| FLOAT32 | 单精度浮点（pertoken_scale 必需） |

### 2.3 支持的数据格式

| 格式 | 说明 | 维度范围 |
|------|------|----------|
| ND | 常规格式 | 2~6 维 |
| NZ (WeightNz) | 分形格式 | 4~8 维 |
| NZ 原始格式 | Fractal Nz | 4 维固定 |

### 2.4 转置支持

- x1/x2 支持所有转置组合（transA/transB 均可选）
- ND、NZ (WeightNz) 格式全支持
- transB=0 时 MX scale 布局为 `[K/64,N,2]`，transB=TRUE 时为 `[N,K/64,2]`

### 2.5 功能约束

#### 2.5.1 pertoken_scale 约束

- x1Scale (pertoken) 必须 DT_FLOAT (EZ0020)
- 非 G-B/B-B 模式必须 1D[M] 不能 [M,1] (EZ0013)

#### 2.5.2 transpose 一致性约束

- x1 与 pertoken_scale 的转置属性必须一致
- x2 与 scale 的转置属性必须一致
- 例外：相关两维退化为 1×1

#### 2.5.3 batch 广播规则

- numpy 式右对齐广播
- 一方为 1 可广播
- 双方 > 1 不等时报错

## 4. 技术需求

### 4.1 编译环境要求

- CANN Toolkit（与目标芯片版本匹配）
- bisheng 编译器（kernel 编译）
- cmake 构建系统（3.20+）

### 4.2 依赖库要求

#### 4.2.1 omni-ops common 代码

必须引用的 common 模块:
- `matmul_util.cpp/h` - matmul 基础工具
- `debug_tiling.cpp/h` - tiling 调试支持
- `op_cache_tiling.cpp/h` - op cache tiling
- `runtime_kb_api.cpp/h` - **运行时知识库 API**
- `legacy_common_manager.cpp` - 遗留 common 管理

#### 4.2.2 新增 common 代码

从 ops-nn 迁移到 omni-ops common:
- `log_format_util.h` - 日志格式工具（v3/v4 硬依赖）
- `quant_matmul_v4.{h,cpp}` - V4 l0op executor（v3+v4 共享）

### 4.3 A2A3 芯片架构要求

#### 4.3.1 芯片识别条件

代码中使用以下条件识别 A2A3:
```cpp
// C++ 条件编译
#if __CCE_AICORE__ == 220

// C++ 运行时检查
npuArch == NpuArch::DAV_2201
socVersion == SocVersion::ASCEND910B || socVersion == SocVersion::ASCEND910_93
```

#### 4.3.2 A2A3 与其他芯片的差异

| 特性 | A2A3 (910B/910C) | A5 (950) | 310P |
|------|------------------|----------|------|
| __CCE_AICORE__ | 220 | 3510 | 200 |
| Regbase 编程 | ❌ 不支持 | ✅ 支持 | ❌ |
| SIMT 编程 | ❌ 不支持 | ✅ 支持 | ❌ |
| MX 量化 | ❌ 不支持 | ✅ 支持 | ❌ |
| KB 机制 | ✅ 支持 | ✅ 支持 | ✅ |

#### 4.3.3 kernel 实现条件

所有 kernel 实现必须在 `#if __CCE_AICORE__ == 220` 保护下:
```cpp
#if (defined(__CCE_AICORE__) && __CCE_AICORE__ == 220) || \
    (defined(__NPU_ARCH__) && (__NPU_ARCH__ == 3003 || __NPU_ARCH__ == 3113))
#include "quant_batch_matmul_v3_cube_basic.h"
// ...
#endif
```

### 4.4 知识库（KB）迁移要求

#### 4.4.1 KB 文件迁移

**源位置**: `ops-nn/matmul/quant_batch_matmul_v3/op_host/config/ascend910b/`

**目标位置**: `omni-ops/.../ai_infra_quant_batch_matmul_v3/op_host/config/ascend910b/`

**文件改名**:
- `*_runtime_kb.json` → `*AiInfraQuantBatchMatmulV3_runtime_kb.json`

#### 4.4.2 KB 内容修改

使用 sed 修改 JSON 内的 `"op"` 字段:
```bash
sed -i 's/"op": "QuantBatchMatmulV3"/"op": "AiInfraQuantBatchMatmulV3"/g' *_runtime_kb.json
```

#### 4.4.3 KB 验证要求

- [ ] KB 文件存在且可读
- [ ] KB JSON 格式正确
- [ ] KB 内 `"op"` 字段已更新
- [ ] 运行时能正确命中 KB tiling

### 4.5 编译配置

#### 4.5.1 全局编译配置

```cmake
add_ops_compile_options(
    OP_NAME AiInfraQuantBatchMatmulV3
    OPTIONS --cce-auto-sync=off
            -Wno-deprecated-declarations
            -Werror
)
```

#### 4.5.2 芯片配置

- vendor_name: `omni_custom_transformer`
- 编译目标: `ascend910b`, `ascend910_93`
- 不编译: `ascend950`, `ascend310p`, `kirin*`

#### 4.5.3 KB 注册配置

确保 KB 机制在 CMakeLists 中正确引用:
```cmake

    ...
    ../../common/src/op_host/runtime_kb_api.cpp
    ...

```

## 7. 风险与限制

### 7.1 已知风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| v5 接口位置错误 | aclnn 接口无法找到 | 确保 v4/op_host/op_api/ 移到 v4/op_api/ |
| CMake 依赖缺失 | 编译失败 | 对比 ai_infra_matmul 逐项检查 |
| 命名漏改 | dispatch 静默断 | 全 grep 确认无残留 |
| arch20 挂钩未删全 | transpose 依赖残留 | 4 处挂钩逐行删除 |
| KB 改名不一致 | runtime_kb 无法命中 | 文件名 + 内容 sed |

### 7.2 技术限制

- 仅支持 A2A3 芯片
- 不支持 MX/mxfp4（950-only）
- 不支持 fp8/hifloat8 perblock
- 不支持 B-B、T-CG 模式

### 7.3 范围排除

- A5 (Ascend 950) 所有相关代码
- 310P (arch20) 所有相关代码
- Kirin 系列芯片
- op-plugin 融合变体（gelu/reduce_sum/dequant/add_）
- transpose 算子依赖（已通过删除 arch20 挂钩解除）
